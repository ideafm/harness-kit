# tw-web

Локальная панель управления Tw. Панель развивается через сам harness:
задачи проходят планирование, реализацию, проверки и независимое ревью.
Контроллер и ограничения остаются в соседнем `../harness-kit`.

## Что готово

Запускаемый каркас: стартовая страница, HTTP-сервер на 127.0.0.1 и launcher.
Реальные задачи ещё не подключены; стартовая страница явно показывает это.
Python 3.11+, стандартная библиотека, без установки зависимостей.

```sh
cd /Users/twist/tmp/ai/tw-web
python3 bin/tw-web
python3 bin/tw-web status
python3 bin/tw-web stop
```

Команда без аргументов запускает фоновый сервер и открывает браузер.
Если сервер уже работает, открывается тот же экземпляр. `start` запускает
без открытия браузера; `--no-browser` также отключает открытие.
Выделенный адрес — http://127.0.0.1:47831. Если порт занят другим
процессом, запуск завершится ошибкой без смены порта.
Закрытие вкладки не останавливает сервер. `stop` не останавливает worker Tw.
Никаких глобальных настроек, автозапуска, LAN-доступа или публикации.

Для короткой команды можно добавить bin в PATH только текущего терминала:

```sh
export PATH="/Users/twist/tmp/ai/tw-web/bin:$PATH"
tw-web
```

Runtime-state, блокировки и лог принадлежат launcher и хранятся в `.tw-web/`;
они не попадают в Git. Отдельная папка сохраняет возможность выполнить
`tw init`, даже если панель была запущена раньше подключения harness.
PID не используется для принудительного kill: остановка требует ответа
именно нашего сервера. Host, Origin и управляющие запросы проверяются.

## Проверки

```sh
python3 -m unittest discover -s tests -v
```

15 тестов проверяют маршруты, защиту запросов и lifecycle с подставленным
транспортом. Они проходят и внутри текущего sandbox harness без сокетов.
Отдельный локальный HTTP smoke проверил три одновременных запуска, один
сервер, ответ страницы, отклонение чужих Host/Origin и штатную остановку.
Browser QA пока не выполнялся.
