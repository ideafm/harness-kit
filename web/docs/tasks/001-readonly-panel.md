# Первая задача через harness: читающая панель tw-web

Развивай существующий каркас tw-web, не меняя соседний harness-kit.
Сначала сохрани спецификацию, план и сводку, затем реализуй и проверь результат.

Добавь список настоящих задач и карточку выбранной задачи. Важнее всего
ожидающие вопросы, блокировки и результаты на приёмке. Показывай отдельно этап
и состояние, текст вопроса/причину остановки, время следующей попытки при лимите,
а также состояние worker. В карточке доступны спецификация, план, сводка,
diff, проверки и ревью; отсутствующий артефакт имеет понятное пустое состояние.
Обновление через polling. Русский интерфейс, адаптация к узкому экрану.
Не показывай вымышленные задачи или проценты готовности.

Интеграция: используй ограниченный stdio MCP `../harness-kit/bin/tw-mcp`
с фиксированным `--project` и только tw_status, tw_show, tw_artifact.
Запускает его сервер панели вне sandbox агента; путь к контроллеру задаёт
оператор при старте, браузер не выбирает пути. Код контроллера недоступен
из snapshot: опирайся на контракт ниже, тестируй с подставленным транспортом.
Не пытайся читать соседние папки, hidden paths или .harness в исходном проекте.

MCP — JSON-RPC 2.0, одна JSON-строка на сообщение в stdin/stdout. Сначала
initialize, затем notifications/initialized, затем tools/call. Результат
tools/call содержит content[0].text с JSON либо isError=true. Процесс нужно
корректно закрывать; таймаут и лимит размера вывода обязательны.

Контракты инструментов:

- tw_status, аргументы {}: {project: string, tasks: Task[], worker: object}.
- tw_show, {task: integer >= 1}: Task.
- tw_artifact, {task: integer >= 1, artifact: string}: {task, artifact, text,
  truncated}. Имя — specification, plan, summary, diff, checks или review.
- Task: id, state, stage, updated, request, artifacts: string[]. Дополнительно
  могут присутствовать question, question_kind, reason, retry_at,
  implementation_summary, review_verdict. Времена — Unix seconds.
- Worker: running: boolean; дополнительно pid, starting, managed_elsewhere.

В браузере нет путей, shell-команд и произвольных имён инструментов. API
ограничивается чтением этих данных. Не дублируй состояния и не открывай SQLite.
Текст задач и артефактов выводи только через textContent. Приёмка, применение,
постановка задач и изменения контроллера не входят в эту задачу.

Сохрани свойства launcher: один сервер на 127.0.0.1:47831, без выбора
другого порта при конфликте, проверка Host/Origin,
защищённая остановка, независимость от worker. Runtime-state и MCP доступны
только доверенному серверу, не браузеру. Не отдавай instance token клиенту.

Проверки: python3 -m unittest discover -s tests -v. Тесты внутри sandbox
не открывают сокеты и не запускают настоящий контроллер: подставляй транспорт,
проверяй ошибки протокола/таймауты, допустимые действия и параметры, маршруты,
пустые состояния и данные. Никаких зависимостей, доступа к сети, browser QA
или ослабления sandbox. Если нужен engine fix — запиши проблему и останови
зависимую часть, не правь harness-kit. Результат оставь на приёмке человека.
