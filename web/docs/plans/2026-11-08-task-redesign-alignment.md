# План: Согласование компонентов интерфейса tw-web и проверка действий

## Контекст и цели
Продолжение редизайна веб-интерфейса `tw-web` для достижения цельного, согласованного и безопасного результата.
Выбор модели в форме создания задачи остаётся отключённым (`disabled`) без передачи или имитации в API.
Изменения затрагивают только файлы в `web/**` без изменения `harness/**` и корневых файлов Harness Kit.

## Задачи и этапы

1. **Форма создания задачи (`web/components/create-task-sheet.tsx`):**
   - Выбор модели: чётко зафиксирован как отключённый (`disabled`, `cursor-not-allowed`, бейдж «скоро», подсказка). В API отправляются только разрешённые поля `{ request, approval_mode }` (и опционально `placement`).
   - Инициализация `autoStart`: синхронизация с восстановленным `restored.body.placement`.
   - Проверка лимитов (50 КиБ), обработка ошибок, повторные запросы при `pending` с сохранением ключа идемпотентности.
   - Сохранение контрактов для тестов (`＋ Новая задача`, `Запрос`, `Режим утверждения`, `Создать задачу`).

2. **Действия и карточка задачи (`web/components/task-card.tsx` и `web/components/task-actions.tsx`):**
   - Соответствие действиям контроллера: поддержка только разрешённых действий `ACTIONS` (`start`, `pause`, `resume`, `answer`, `approve_plan`, `revise_plan`, `accept_result`, `request_changes`, `reject_result`).
   - Отключённые возможности: удаление задачи (не поддерживается API) и неинициализированная ветка git отображаются отключёнными, без скрытия `title`-подсказок (убран `pointer-events-none`).
   - Статус операций: гарантированный показ `role="status"` и информационных сообщений при запуске, паузе, возобновлении и повторении команд независимо от режима модального ответа.
   - Очистка от артефактов и согласованность визуального стиля карточки и списка задач.

3. **Стили и консистентность интерфейса:**
   - Согласованность тёмной и светлой тем.
   - Единая палитра бейджей статусов пайплайна и задач.

4. **Контролируемые проверки:**
   - Запуск frontend-тестов: `npm --prefix web test` (147 тестов).
   - Запуск проверки типов: `npm --prefix web run typecheck`.
   - Сборка production-бандла: `npm --prefix web run build`.
   - Актуализация receipt и проверка перезапуска `tw-web`.
   - Запуск полного набора тестов бэкенда: `bash tests/run.sh` (228 тестов).
   - Остановка без автоматического принятия, применения или коммита.
