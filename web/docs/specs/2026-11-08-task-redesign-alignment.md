# Спецификация: Согласование компонентов интерфейса tw-web и проверка действий

## 1. Область действия
Реализация интерфейса оператора `tw-web` в каталоге `web/`.
Файлы ядра `harness/**` и корневые файлы проекта не изменяются.

## 2. Требования к форме создания задачи (`CreateTaskSheet` / `CreateTaskModal`)
- Диалоговое окно по центру экрана (`radix-ui` `Dialog.Root`).
- Текстовое поле «Запрос» с лимитом 51200 байт.
- Выбор режима утверждения: `approve-plan` / `auto`.
- Выбор модели рассуждений: отображается, но находится в отключённом состоянии (`disabled`, `opacity-75`, `cursor-not-allowed`, подсказка). Никакие параметры модели не передаются в API.
- Чекбокс немедленного запуска (`autoStart`): по умолчанию включён, при снятии передаёт `placement: 'backlog'`. При повторении запроса инициализируется из `restored.body.placement`.
- Строгое соблюдение формата отправки: `{ request, approval_mode [, placement] }`.
- Обработка ошибок контроллера (4xx очищает зависший pending, сетевые ошибки сохраняют ключ идемпотентности).

## 3. Требования к действиям оператора (`TaskActions` / `TaskCard`)
- Поддерживаются только действия контроллера:
  - `start`, `pause`, `resume`: обычные кнопки, опрос `operations/{id}`.
  - `answer`: ответ на вопрос агента (модальный или строчный), опрос `operations/{id}`.
  - `approve_plan`, `revise_plan`, `accept_result`, `request_changes`, `reject_result`: доверенные виджеты (`TrustedDecisionWidget`) через изолированный iframe confirmation origin.
- Неподдерживаемые API действия (удаление задачи, фиктивные кнопки) не должны создавать впечатление работоспособности: помечаются `disabled`, `cursor-not-allowed`, без перехвата `pointer-events-none`, чтобы всплывающие подсказки с объяснением были доступны.
- Сообщения статуса (`role="status"`) видны при выполнении любой команды (`start`, `pause`, `resume`, `answer`, повтор), отображая ход выполнения или ошибку.
