# TASK-004 · спецификация UI · версия 2

Основа — подготовленная контроллером TASK-003, source_state=accepted во входном receipt. Самостоятельная проверка происхождения и независимые проверки не выполнены. Изменения ограничены разрешёнными frontend-файлами, тестами и документацией. Backend, transport, зависимости и инфраструктура не меняются.

## Выбранное направление

Пользователь разрешил A «Фокус» с палитрой B: фон #f5f6f8, поверхности #ffffff, акцент #466d91, границы #e5e9ed, текст #26323d. Sidebar проектов, список задач и карточка решения видны рядом. Системный шрифт 14–16 px, заголовки 20–24 px, шаги отступов 4/8/12/16/24 px, радиусы 8–12 px. Собственные декоративные SVG, существующие shadcn/Radix, без новых зависимостей.

Основной экран: заголовок проекта, worker, создание задачи; строка поиска и фильтров «Все / Нужно вам / Бэклог»; список по пять задач; карточка с фактическими сводкой, причиной, вопросом и разрешёнными действиями. Проекты имеют поиск и страницы по восемь элементов. Выбор задачи и проекта остаётся в URL. Страница корректируется при обновлении массива, поиск и фильтр сбрасывают страницу. Бэклог отображается только по фактическому state=backlog, без переходов или scheduler на frontend.

Этапы — точки с русскими подсказками по hover/focus, доступными именами и aria-current. Предыдущие этапы не объявляются успешно проверенными. Неизвестные сочетания сообщаются явно. Длинные существенные данные не обрезаются. Целевые размеры: 1366×768, 1440×900, 390×844, 320 px и масштаб 200%. На узком экране список и карточка переключаются с явным возвратом; проекты доступны через Sheet.

## Подробности

«Исходная задача» показывает полный task.request безопасным текстом. План, изменения, проверки, ревью и история открываются по запросу в Radix Dialog с заголовком, Escape, удержанием и возвратом фокуса. Единственная область прокрутки — тело модалки. Артефакты загружаются при открытии, различают отсутствие, загрузку, ошибку, пустоту и усечение. История содержит фактические события; она не подменяет структурированное объяснение причины.

Карточка не придумывает рекомендации по exit_code или исчерпанию попыток. При отсутствии рекомендаций предлагает открыть доказательства. Вопрос отображается только из task.question. Приёмка и применение различаются.

## Доверенные решения

HIGH_ACTIONS не отправляются через JSON POST. approve_plan и accept_result представлены встроенной trusted iframe-кнопкой; замечания и отклонение — встроенной формой в модалке. Единственный источник — control.confirmation_widgets при актуальном allowed_actions и session с csrf. confirmation_urls не используется как fallback.

URL: http loopback, точный session.confirmation_origin, pathname=/confirm/embed, без credentials/fragment. Iframe sandbox="allow-forms allow-scripts allow-same-origin", доступный title. Авторизация, поля и финальное подтверждение принадлежат контроллеру.

Сообщения требуют точных event.origin и event.source===iframe.contentWindow. tw:decision дополнительно требует task/project/action/status=succeeded; результат только перечитывается. tw:widget-size требует конечного числового height, ограниченного 40..420 px. Смена проекта/task/revision/URL и отзыв действия демонтируют старую форму. Реальные размеры форм и отсутствие вложенной прокрутки требуют проверки контроллером.

## Worker и preview

Живой worker не означает выполнение задачи. Активная задача определяется worker.task_id и наличием задачи в текущем проекте. Observation из worker или активной задачи принимается только при совпадении task_id, mode=events, interactive=false и строковой terminal_command. Команда копируется без изменений, не запускается; при отказе clipboard доступно ручное выделение readonly-поля. Смена проекта очищает панель и команду.

Preview URL берётся только из task.preview.url, проверяется как http loopback без credentials/fragment. Отсутствие csrf допускает чтение, но исключает команды и восстановление полномочий. Worker независим от браузера.

## Сохранность и предпосылки

Сохраняются создание, start/pause/resume, ответы, проектные pending-слоты, исходные ключи/revision, CSRF/If-Match/Idempotency-Key, восстановление неопределённых операций и защита от поздних ответов. Недоверенный текст не выполняется как HTML или shell.

Отдельные backend-задачи: B-002 (очередь/import/scheduler/зависимости), структурированные причины и результаты проверок, рекомендации человеку, назначение/время/события процесса, live-канал и сохраняемые сообщения с доставкой, provenance baseline. Frontend их не имитирует. Для TASK-003 resume не доказывает исправление причины; фактические успешные проверки не равны приёмке.

## Допущения и проверка

Поиск и страницы используют полный status.tasks; заголовок берётся из первой строки task.request. Отсутствующие поля считаются недоступными. Число элементов страницы фиксировано для компактности. Разрешён только подготовленный контроллерный toolchain.

Нужны controller typecheck, interaction, build и Python unittest, а также визуальная проверка размеров, 200%, контраста, клавиатуры и реальных iframe. Агент их не запускал и не утверждает прохождение. Результат остаётся на человеческой приёмке, без коммита и применения.
