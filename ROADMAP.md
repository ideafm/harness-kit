# tw — harness-kit

Учебный конструктор рельсов для агентской разработки. Каждый шаг — одна идея: зачем, сборка, живая проверка, разбор кода.

## Pipeline: цель → спецификация → план → loop → проверка → приёмка

| Этап | Деталь | Статус |
|------|--------|--------|
| Цель → спецификация | skill `tw:spec`: вопросы по одному, с вариантами через `AskUserQuestion` (в headless — нумерованным списком), `docs/specs/…md` по шаблону, гейт «утверждаешь?» | готово: RED 3/3 строили сразу и выдумывали данные; GREEN 3/3 вызвали skill, 0 файлов до утверждения; на ясной задаче не срабатывает. Любая формулировка задачи («есть проблема», «как решить», «надо поправить», «надо, чтобы…», «пользователи жалуются», голое описание): RED — без «к вечеру» 0/3, сразу правки; правило в SessionStart + описание skill → GREEN 8/8 на финальной версии (5 формулировок), 0 файлов; контроль: однозначный баг 0/3 (чинит сразу), вопрос «как устроено» 0/2 |
| Спецификация → план | skill `tw:plan`: 2–7 задач, у каждой «Проверка» и «Закрывает» пункт спеки, `docs/plans/…md`, гейт «утверждаешь план?»; spec после «да» передаёт в plan | готово: RED 2/2 — в окружении с superpowers план есть, но чужой (117–163 строк, docs/superpowers/, без статуса и журнала); GREEN 3/3 — `tw:plan`, 34–39 строк, у всех задач проверка, 0 файлов кроме плана; на простой задаче не срабатывает |
| Loop исполнения | Stop-hook: тесты до зелёного + scope против плана | готово: живой прогон — сломанный руками код, вопрос агенту → блок «круг 1 из 3» → починил → green |
| Перепланирование | правило в `tw:plan` («Исполнение»): план неверен → сначала правка плана и строка в «Журнал», потом код; подталкивают hooks: scope — «файл не в плане: откати или впиши задачу», проверяющий — «нет» → статус «в работе», доработка с записью в журнал. Отдельного hook нет | готово: в учебном прогоне агент дважды заметил вырезанную из утверждённого плана задачу (сверил с утверждённым; по полю «Закрывает»), добавил задачи 3–4 с записью в журнал; после «нет» проверяющего принёс 2 варианта правки спеки, по выбору человека добавил задачи 6–7. Открыто: нет детерминированной проверки «план изменён раньше кода» |
| Проверка и приёмка | Stop-конвейер: тесты → scope → независимый проверяющий (свежий `claude -p` только на чтение, видит спеку и diff, вердикт по каждому пункту «Готово, когда»: да / нет / человек); затем карточка одобрения `/tw:accept`; коммит — только после «да» пользователя | проверяющий готово: на учебном прогоне 8/9 + 1 человеку; живой e2e — план «забыл» пункт спеки, тесты зелёные, проверяющий не подтвердил → агент перепланировал с записью в журнал, доделал → 4/4. ~25 с и ~$0.1 на проверку. Карточка одобрения — шаг 6, готова. Наблюдаемость (2026-10-23): метки этапов `[tw · N/5 …]` в ответах агента (skills) и строки `tw ▸ тесты / scope / проверяющий` от Stop-hook через `systemMessage` |

## Рельсы

| # | Шаг | Чему учимся | Статус |
|---|-----|-------------|--------|
| 0 | Каркас плагина, метка проекта `.claude/tw.json`, `/tw:init` | Как плагин попадает в Claude Code; почему hooks срабатывают только в своих проектах | готово; init работает и на пустой папке (`{}`), hooks сами берут `npm test`, когда появится скрипт `test` |
| 1 | Prettier на каждый Edit/Write | PostToolUse, JSON на stdin, matcher | готово: в живых сессиях агент получал «переформатирован prettier, перечитай» |
| 2–3 | Stop: «готово» только на зелёных тестах; тесты гоняем, только если на диске есть файлы новее последней проверки; круги 1–2 чинит сам, на 3-м или при застревании — свежий субагент: модель и effort hook читает из транскрипта, не Opus → Opus, Opus → effort+1 (не прочитал — `escalateEffort`), дальше — человек | Loop, предохранитель, эскалация; следить за фактами на диске, а не за инструментами агента | проверено в headless-сессии; SessionStart больше не ставит метку «проверено» — правки между сессиями тоже проверяются |
| 4 | Guard: секреты (Read/Edit/Write/Bash); код меняется только через Edit/Write; комментарии запрещены в новых строках, если в последнем сообщении пользователь их не просил | PreToolUse `deny`; закрывать обходные каналы; hook читает транскрипт для контекста | готово |
| 4.5 | Память между сессиями | Встроенная auto memory (MEMORY.md, 200 строк / 25KB) включена; своя память решений проекта — по итогам пары дней | auto memory включена |
| 5 | План = ledger: статус (черновик → в работе → готов/брошен), `[x]` только после проверки, «Журнал» по строке на задачу; SessionStart показывает незакрытые планы и следующую задачу | Состояние вне контекста; агент не продолжает сам, а сверяется с запросом | готово: hook проверен на 3 планах (готовый скрыт); с двумя планами агент спросил какой; при исполнении не поставил `[x]` без проверки и записал перепланирование в журнал |
| 5.1 | Приоритет tw над superpowers: SessionStart в tw-проекте велит брать tw:spec / tw:plan вместо brainstorming / writing-plans / executing-plans | Правила процесса — через hook, а не надежду на описание skill | готово; 2026-10-23 добавлено: баг-репорт и любая формулировка задачи → tw:spec вместо systematic-debugging (RED/GREEN — в строке «Цель → спецификация»); язык сообщений — язык пользователя |
| 5.2 | `/tw:status`: pipeline одним экраном — что включено, последний прогон тестов, активные планы, прогресс, приёмка, хвост журнала | Наблюдаемость рельс; экран для демо | готово: проверено в живой сессии |
| 6 | Карточка одобрения | Дешёвая ручная приёмка | готово: `/tw:accept` + `scripts/accept.sh` — сделано, вердикты проверяющего, «На тебе» (`человек`), допущения спеки, diff по файлам, хвост журнала; «принято» → отметка приёмки + журнал + вопрос про коммит, «доработать» → план снова «в работе». Коммит только после «да». Проверено: карточка на двух проектах; живьём агент после проверяющего не коммитил и сам отправил к `/tw:accept`. Сам `/tw:accept` в headless не запускается (команда только для человека); 2026-10-23 карточка показана в интерактивной сессии, ветка «принято» → коммит живьём ещё не пройдена |
| 7 | Scope-проверка: diff против плана | Ловить расхождение с планом до человека | готово: `hooks/scope.sh` на Stop — git status против HEAD; файл из «Не трогаем» спеки или не упомянутый в плане/спеке → блок один раз, повтор → человеку; бюджет `diffBudget` убран 2026-10-28 — агент не должен ужимать работу под число строк, размер diff только показывается. Текущий план — «в работе» или изменён после коммита. Живьём: агент сам отказался трогать файл из «Не трогаем»; чужую правку руками не откатил, а спросил. 2026-10-23: «Не трогаем» запрещает файл, только если путь в перечислении стоит сам (можно с пояснением после) — «список services в `src/catalog.ts`» больше не блокирует весь файл; в `tw:plan` красный флаг «задача правит файл из «Не трогаем»» |

## Устройство

- `tests/run.sh` — сценарии исполнителя, приёмки и Stop-hook на временном git-проекте с фейковым `claude` (`tests/fakebin/claude`): подготовка, приёмка/застряла, повтор на Opus, лимит, остановка, слияние, конфликт, rebase, доработка, отклонение. Запуск перед каждым коммитом: `bash tests/run.sh` (один сценарий — `bash tests/run.sh accept`), ~15 с, без сети и токенов.
- `.claude-plugin/plugin.json` — манифест, имя `tw` даёт префикс командам: `/tw:init`.
- `skills/init/` — команда подключения проекта.
- `skills/estimate/` — оценка задач (вне pipeline).
- `skills/scout/` — разведка проекта → `docs/backlog/`.
- `skills/task/` — задача в бэклог `docs/backlog/B-NNN.md`.
- `skills/spec/`, `skills/plan/` — спецификация и план (план = ledger).
- `skills/status/` + `scripts/status.sh` — `/tw:status`.
- `skills/accept/` + `scripts/accept.sh` — `/tw:accept`, карточка одобрения; для бэклога — действия `merge`, `rework`, `reject`, `rebase`, `ui`.
- `skills/run/` — `/tw:run`, набор задач и запуск исполнителя.
- `hooks/hooks.json` — какие события ловим; пути через `${CLAUDE_PLUGIN_ROOT}`.
- `hooks/session-start.sh` — правила процесса в контекст (tw главнее superpowers, когда звать spec) и незакрытые планы.
- `hooks/guard.sh` — PreToolUse: секреты, правка кода только через Edit/Write, запрет комментариев, подавлений проверок и правки их конфигов вне плана.
- `hooks/format.sh` — PostToolUse: prettier.
- `hooks/stop.sh` — Stop-конвейер: `check` (или тесты) → `scope.sh` → `verify.sh`; первый блок останавливает, метка «проверено» — только после всего конвейера; по шагу печатает строку `tw ▸`.
- `hooks/scope.sh` — scope-проверка.
- `hooks/verify.sh` — независимый проверяющий; вложенный claude запускается с `TW_NESTED=1`, чтобы tw-hooks не рекурсировали. Настройки в `tw.json`: `verify`, `verifyModel`, `verifyRounds`, `verifyTools`.
- `scripts/watch.sh` — просмотр хода исполнителя в терминале: `run.log` и поток текущей задачи; `open` — сплит справа (Ghostty/iTerm2 через AppleScript, tmux). Панель-модуль убрана 2026-10-28: не прокручивалась, а обычный терминал даёт прокрутку и поиск даром.
- `scripts/backlog.sh` — бэклог: поля и статусы задач, очередь, `prepare` (спека и план → ветка задачи без checkout), `running` (pid исполнителя).
- `scripts/run.sh` — исполнитель бэклога в worktree `.claude/worktrees/tw-run`; `run.sh stop` — остановка.
- `hooks/lib.sh` — общий вход для всех hooks: ищет `.claude/tw.json` вверх от `CLAUDE_PROJECT_DIR`; нет метки — hook молча выходит.
- Состояние проекта — `.claude/tw-state/` (в `.gitignore`).
