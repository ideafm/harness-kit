# Разведка → бэклог

Каждое своё сообщение пользователю на этом этапе начинай с метки отдельной строкой: `**[tw · разведка]**`.

Бэклог — очередь, из которой задачи берут в `tw:spec`, а потом, возможно, без человека. Пункт без доказательства — мнение: его нельзя ни взять в работу, ни отклонить по фактам. Список в чате теряется со следующей сессией.

**Код не меняешь.** Единственный файл, который пишешь, — `docs/backlog.md`.

## Процесс

1. Прочитай `docs/backlog.md`, если есть. Чужие пункты не удаляй и не переписывай по смыслу: пункт без формата переведи в формат, текст сохрани, «Источник: человек». Номера `B-NNN` не переиспользуй.
2. Карта проекта: README, CLAUDE.md/AGENTS.md, пакеты, команды (`tw.json`, `package.json` scripts), прошлые аудиты в `docs/`. Аудит — это подсказка, где смотреть, а не доказательство: каждый пункт из него сверь с кодом сейчас.
3. Запусти то, что проверяется командой: `check` или тесты, typecheck, lint; `grep` по `TODO|FIXME|HACK|\.skip\(|\.only\(`. Новые пакеты не ставь. Упало из-за окружения (нет базы, Docker) — запиши в «Не проверено», не в задачи.
4. Обойди код по категориям: безопасность (доступ к чужим данным, инъекции, секреты в коде — только путь, не значение), корректность (расхождения контрактов api↔web, docs↔код), тесты (критичный код без тестов, `skip`), мёртвый код, инфраструктура. Монорепо из 3+ пакетов — по субагенту `Explore` на пакет с теми же правилами доказательства; итог сводишь сам.
5. Каждую находку подтверди: `файл:строка` и что там, или команда и её вывод. «Не используется» — только после поиска всех способов вызова (строковые ключи, конфиги, роуты). Не подтвердилось — строка в «Не проверено», а не пункт.
6. Отбери 5–20 пунктов. Мелочи одной природы — один пункт. Продукт и бизнес без кода (юристы, интервью, маркетинг) — в раздел «Вне кода», без номеров.
7. Запиши `docs/backlog.md` по шаблону. Открытые пункты — по приоритету.
8. Ответ пользователю: путь, сколько пунктов, топ-5 одной строкой каждый, что не проверено. Предложи: «Скажи номер — оформлю через `tw:spec`». Когда пользователь берёт пункт — статус «спека: docs/specs/…» и вызов `tw:spec` с текстом пункта.

## Шаблон

```markdown
# Бэклог

Разведка: ГГГГ-ММ-ДД · запускалось: <команды и итог одной строкой>

## Открытые

### B-001 · <что не так, языком результата>

- **Статус:** новая
- **Приоритет:** P1 · **Размер:** S · **Категория:** безопасность
- **Где:** `путь/файл.ts:40`
- **Доказательство:** <что в коде или вывод команды>
- **Зачем:** <что сломается или чего не получит пользователь>
- **Готово, когда:** <проверяемое условие>
- **Источник:** tw:scout ГГГГ-ММ-ДД

## Закрытые

## Вне кода

## Не проверено
```

- Статус: `новая` → `спека: <путь>` → `сделана` / `отклонена: <почему>`.
- Приоритет: P1 — потеря данных, денег, доступа или сломанный сценарий пользователя; P2 — риск или заметное неудобство; P3 — гигиена.
- Размер: S — до 2 ч, M — до дня, L — больше дня (такой лучше разбить).
- Повторная разведка: пункт, который больше не воспроизводится, — в «Закрытые» с доказательством.

## Отговорки

| Мысль | Реальность |
|---|---|
| «Выведу список в чат, файл не просили» | Бэклог из чата не переживёт сессию и его не возьмёт ни `tw:spec`, ни ночной прогон. |
| «В аудите уже всё найдено» | Аудит устаревает с каждым коммитом. Пункт без сверки с кодом сейчас — не пункт. |
| «Тесты гонять долго, и так видно» | Вывод команды — самое дешёвое доказательство. |
| «Поправлю мелочь сразу» | Разведка не меняет код: правка без спеки и плана обходит рельсы. |

## Красные флаги — остановись

- Правишь что-то, кроме `docs/backlog.md`.
- У пункта нет `файл:строка` или вывода команды.
- Удалил или переписал пункт, который писал не ты.
- Больше 20 пунктов.
