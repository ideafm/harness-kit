# Набор задач и запуск исполнителя

Каждое своё сообщение пользователю на этом этапе начинай с метки отдельной строкой: `**[tw · набор]**`.

Решения человек принимает сейчас и при приёмке, исполнение идёт без него. Всё, что исполнитель не сможет решить сам, закрывается здесь: спека, план, режим.

Исполнитель работает в отдельном worktree (`.claude/worktrees/tw-run`) и ветке задачи `tw/B-NNN`: папку пользователя он не трогает, ветку в ней не переключает. Спека и план задачи живут в её ветке, в базу они попадут только при приёмке.

`run.sh` и `backlog.sh` ниже — из папки плагина, она напечатана выше.

## Процесс

1. Проверки до вопросов. Исполнитель идёт — покажи хвост `.claude/tw-state/run.log` (5 строк) и остановись: второй не запустится. Бэклог пуст — предложи `tw:scout` или `tw:task` и остановись.
2. Кандидаты: открытые эпики (одним вариантом на эпик: `E1 · эпик · 3/8`, description — заголовок) и задачи вне эпиков со статусами `входящая`, `готова` и `застряла`. Задачи эпиков по одной не предлагай — их берут эпиком. Порядок: сначала P0–P1, потом остальные; внутри приоритета — больший номер первым. Берёшь до 16.
   Аргументы с номерами (`B-009`, `E1`) — это и есть выбор: возьми названные задачи и эпики, шаги 2–3 пропусти. Номер, которого нет в бэклоге или который уже принят, назови одной строкой и пропусти.
3. Спроси одним вызовом `AskUserQuestion`: до 4 вопросов `multiSelect` по 4 задачи, вопрос — «Какие задачи взять? (1/N)», header — `Задачи 1/N`. Вариант: label — `B-001 · P0 · S`, description — заголовок и статус. Кандидатов больше 16 — после ответа одной строкой напиши номера, что не поместились, их можно добавить словами. Ничего не выбрано — остановись.
4. Выбранные `застряла` — `backlog.sh set B-NNN Статус готова "повтор из /tw:run"`: исполнитель продолжит в той же ветке.
5. Выбранный эпик — пакетом. Его задачи: `backlog.sh epic-tasks E1`. Для каждой `входящая` напиши спеку и план сам, как в быстром пути ниже, по тексту задачи, спецификации продукта (поле «Спецификация» эпика) и коду, который уже есть в ветке эпика `tw/E1` (`git show tw/E1:<путь>`; ветки ещё нет — в базе). Покажи одним сообщением: на каждую задачу — «Готово, когда», файлы, задачи плана одной строкой; общие допущения отдельно. Одно `AskUserQuestion`: «Утвердить эпик (рекомендую)» / «Поправить» / «Разобрать задачу X подробно». После «да» — `prepare` по каждой (ветки создадутся от `tw/E1`), в очередь — все готовые задачи эпика, включая `застряла` (статус → `готова`), порядок не важен: исполнитель сам ждёт зависимости.

   Выбранные `входящая` вне эпиков — по одной, в порядке приоритета. Скажи, какая из скольких, и вызови skill `tw:spec` с текстом файла задачи; дальше `tw:spec` и `tw:plan` идут как обычно, с вопросами человеку. Отличия от обычного хода:
   - после «да» по плану поставь `**Статус:** в работе`, но задачи плана не исполняй — это сделает исполнитель;
   - `backlog.sh prepare B-NNN <спека> <план>` — коммитит спеку и план в ветку `tw/B-NNN` (создаёт её от базы), убирает их из рабочего дерева, заполняет поля задачи и ставит `готова`. Сам `git add`/`git commit` не делай и ветку не переключай.
   Человек отказался от спеки или плана — задача остаётся `входящая`, файлы спеки и плана удали, в очередь она не идёт.

   Размер S — быстрый путь вместо разговора: в задаче уже есть «Где», «Доказательство» и «Готово, когда». Прочитай задачу и названный в ней код, сам напиши спеку по формату `tw:spec` и план по формату `tw:plan` (развилки закрой догадками и пометь `[допущение]`). Вопрос раньше утверждения — только если без ответа спеку не написать, и не больше одного. Покажи коротко: пути файлов, «Готово, когда», «Не трогаем», допущения, задачи плана одной строкой каждая. Спроси одним `AskUserQuestion`: «Утвердить спеку и план (рекомендую)» / «Поправить» — что именно, человек впишет / «Полный разговор» — тогда `tw:spec` с вопросами, как для M и L. После «Утвердить» — `**Статус:** в работе` в плане и `prepare`, как выше. Остальные размеры — всегда полный разговор.
6. Выбранные `готова`: у задачи должна быть ветка с планом — `git cat-file -e tw/B-NNN:<план>`. Нет — план и спека лежат в рабочем дереве или в базе: `backlog.sh prepare B-NNN <спека> <план>`, скажи об этом одной строкой. Плана нет нигде — задача на самом деле входящая: веди её по шагу 5.
7. Разрешения. Исполнителю без вопросов доступны только Edit/Write, чтение, скрипты проверки и сборки из package.json (`test`, `typecheck`, `lint`, `format`, `build`, `db:generate`, в том числе через `--filter`), `exec` для vitest/jest/tsc/eslint/prettier, git на чтение и команды из `runAllow` в `.claude/tw.json`. Bash идёт в песочнице: запись только в worktree, сети наружу нет (`runNetwork` — домены-исключения), окружение (`setup`) поднимает сам исполнитель до старта. Пройди по планам выбранных задач: команды из шагов и из «Готово, когда», которые под это не подпадают (`bash deploy/tests/x.sh`, `docker compose …`, `make …`), — спроси одним `AskUserQuestion` (multiSelect): «Разрешить исполнителю?», вариант на команду точной строкой. Выбранные допиши в `runAllow` как `Bash(<команда>)` — точной строкой, без `:*`. Не выбранные — задача застрянет на этой команде, скажи об этом одной строкой.
8. `backlog.sh queue-add` с готовыми задачами в порядке шага 2.
9. Режим — `AskUserQuestion`: «Всю очередь (рекомендую)» — исполнитель идёт, пока очередь не кончится; «Одну задачу» — пробный прогон; свой предел N пользователь впишет в «Other».
10. Запуск из корня проекта: `nohup bash <плагин>/scripts/run.sh <N или 0> >>.claude/tw-state/run.out 2>&1 &` — без привязки к этой сессии, её можно закрыть. Через 5 секунд покажи хвост `run.log`: строка `старт` есть — запущен; нет — покажи `run.out` и остановись. Затем `bash <плагин>/scripts/watch.sh open` — откроет справа просмотр хода (Ghostty, iTerm2, tmux), в другом терминале напечатает команду.
11. Ответ: что в очереди, режим и строки:
    - ход: просмотр справа (если не открылся — `bash <плагин>/scripts/watch.sh` в соседнем окне); весь разговор исполнителя по задаче — `claude --resume <сессия>` из карточки `/tw:accept`;
    - в своей папке можно работать: исполнитель в worktree, но база данных и контейнеры у вас общие;
    - итог — `/tw:status`, приёмка — `/tw:accept`.

## Красные флаги — остановись

- Исполняешь задачи плана сам вместо исполнителя.
- Коммитишь сам или переключаешь ветку — спеку и план в ветку задачи кладёт только `backlog.sh prepare`.
- Ставишь в очередь задачу без утверждённого плана в ветке `tw/B-NNN`.
- Задаёшь вопросы про выбор задач текстом, когда есть `AskUserQuestion`.
