# Разработка tw-web через harness

## Текущее состояние

Подготовлен запускаемый каркас и первая задача читающей панели. Пользователь разрешил исходный коммит подготовленного каркаса tw-web.
После baseline подключаем Tw и запускаем первую задачу. Для последующих
коммитов требуется отдельная авторизация.

## После разрешённого исходного коммита

```sh
cd /Users/twist/tmp/ai/tw-web
python3 ../harness-kit/bin/tw init --check 'python3 -m unittest discover -s tests -v'
python3 ../harness-kit/bin/tw
```

В Tw попросите выполнить задачу из `docs/tasks/001-readonly-panel.md`.
Skill и MCP поставят её внешнему worker. Закрытие чата или вкладки панели
не останавливает worker. Результат остаётся на приёмке человека.

Команда без чата для наблюдения:

```sh
python3 ../harness-kit/bin/harness --project /Users/twist/tmp/ai/tw-web status
```

Нельзя применять taskboard helper к этому проекту. Общее безопасное применение
результата пока не реализовано; приёмка и интеграция остаются отдельными действиями.
Исправления ядра оформляются и проверяются отдельно в harness-kit.

## Открыть панель

```sh
python3 bin/tw-web
python3 bin/tw-web status
python3 bin/tw-web stop
```

Сейчас это стартовая страница. Реальные задачи появятся после первой задачи
через harness и принятой интеграции. Панель не обновляет свой код автоматически.
Unit-тесты не открывают сокеты и проходят в строгом sandbox. Настоящий HTTP
smoke выполняется снаружи sandbox агента, без изменения его разрешений.
Browser QA не выполняется без отдельного разрешения по AGENTS.md.
