## Исправлено: область frontend preview

Runner проверяет Next из workspace/<scope>, но Preview использовал workspace для digest и сборки. Это приводило к ложному current=false и сбоям пересборки. Preview теперь разрешает scope тем же Runner.task_scope_dir, проверяет существование и отсутствие ссылок во всех компонентах scoped пути, использует соответствующий frontend toolchain при его наличии. ProjectView использует такую же область для отслеживания изменений и сборки. Задачи без scope сохраняют прежнее поведение.

Регрессионные тесты проверяют совпадение digest, независимость от изменений core, обнаружение frontend изменений, выбор scoped toolchain, отказ для отсутствующего каталога и ссылки. Изменения находятся в harness/preview.py, harness/project_view.py, tests/codex/test_git_preview.py.

## Подтверждённые оставшиеся проблемы

1. **Переключение исполнителя.** Operator.dispatch(switch_backend) меняет data.backend, а Runner.task_backend отдаёт приоритет data.stage_backends[stage]. Для задач с поэтапными переопределениями кнопка может фактически не переключить исполнителя. Требуется определить семантику переключения текущего этапа и согласовать отображение с реальным backend; добавить тест именно такого сочетания.
2. **Удаление задач не завершено.** В UI есть отключённая кнопка, но в Operator.ACTIONS нет удаления и восстановления. Спецификация обратимого удаления не означает готовность функции. Не добавлять физическое удаление истории в качестве сокращения пути.
3. **Документация переноса устарела.** web/AGENTS.md всё ещё описывает соседний ../harness-kit, README web содержит исторические отчёты итераций и прежний launcher. Нужна отдельная актуализация договорённостей, команд и архитектуры; правила безопасности сохранять.
4. **Версии интерфейса заданы литералами.** Sidebar показывает v0.9.4, header — v0.2.0. Они не являются достоверными версиями сборки. TASK-012 с просьбой убрать бейдж находится на приёмке; не принимать её за пользователя и не дублировать её изменение автоматически.
5. **Не весь runtime проверен живым агентом.** Тесты адаптеров и песочницы проходят, но новый платный цикл с Codex/Gemini в ходе аудита не запускался. Нельзя считать этот проход полной сертификацией изоляции.

## Исправления после ревью

По следующему поручению пользователя создан коммит 9062c94, затем выполнены исправления из списка выше:

- Явный switch_backend теперь закрепляет выбранный backend во всех этапах. Старые stage_backends остаются в событии backend_switched. API показывает backend текущего этапа, а не только общий fallback. Явные модели этим действием не меняются.
- Добавлены серверные delete/restore и trashed, исключение из очереди, запрет удаления running, сохранение предыдущего состояния. Восстановление queued/rate_limited возвращает paused; вопросы, планы и результаты возвращаются в прежнее неработающее состояние.
- UI использует подтверждение удаления, существующий идемпотентный transport и фильтр «Удалённые». Массового и физического удаления нет. Сняты устаревшие отключённые иконки удаления в строках; управление доступно в выбранной карточке.
- Начало выполнения использует CAS по revision времени; поздняя ошибка preflight не перезаписывает trashed. HTTP-тест проверяет CSRF, устаревшую revision, повтор POST и отдельный GET результата операции.
- Убраны фиксированные версии UI. Это прямое исправление по поручению пользователя, а не приёмка TASK-012. Её статус не изменялся.
- Документация web описывает монорепозиторий и актуальный launcher. Исправлен путь legacy operator. Остальные legacy launcher/preview явно отмечены как неподдерживаемые для текущего Next UI.

Проверки: 251 core, 152 frontend, 20 web Python; TypeScript и production build успешны. Playwright на отдельной сборке с подставленным API подтвердил delete → корзина → restore; ширина документа при viewport 390 px равна 390 px. Реальные задачи, действующий worker и deployment не изменялись.
