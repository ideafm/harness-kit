# Автоматическое продолжение очереди

Пользователь поручил самостоятельно брать следующие задачи без лишних вопросов.
Рутинные этапы и выбор порядка выполняет контроллер; приёмка, коммиты, merge
и защищённые ресурсы сохраняют отдельные разрешения. Согласованный план и
его версия не подменяются общим поручением. Расход контролируется quota_guard.

Первый шаг — восстановить TASK-003: отдельно повторить ревью только при
совпадении текущих изменений и check_receipt, хэша check.log и frontend source
receipt. Сохранить прежний отказ и попытки, не менять критерии утверждённого
плана. Ревью получает проверенный факт утверждения конкретной версии и текущий
этап: ограничения исторического этапа планирования не отменяют последующее
разрешение реализации. Неразрешимый конфликт критериев требует human с точным
объяснением, а не бесконечных исправлений готового кода.

Resume начинает новую волну попыток оставшихся этапов, сохраняет прошлые
счётчики в событии. Check/review не должны блокироваться из-за предыдущей волны.
TASK-004 получает проверенную основу TASK-003 с сохранением всех накопленных
UI-требований. Затем выполняется дизайн-план; критерии для результата описывают
конечную функциональность, не временный запрет реализации на этапе планирования.
