# Редизайн tw-web · спецификация v1

Переданный контекст контроллера сообщает о событиях runtime_prepared и plan_approved с точной версией v1 в controller_authorization_events; они служат основанием продолжения реализации. Этот документ сам по себе не доказывает первоначальное утверждение. Утверждение не предоставляет доступа к защищённым ресурсам. TASK-001 не предполагается принятым.

Самостоятельный frontend: Next App Router, TypeScript, Tailwind v4 и подготовленные официальные shadcn-компоненты. Статический экспорт, build-next, системные шрифты. Версии зависимостей и lockfile принадлежат подготовке контроллера и не изменяются агентом.

Русская панель содержит sidebar одного подключённого проекта, реальные счётчики, блок решений, очередь, компактную карточку и шесть вкладок. Исходный запрос свёрнут. Отсутствующие данные не подменяются задачами или прогрессом. Неизвестные состояния отображаются буквально. Запросы, события и артефакты выводятся текстом. На мобильном sidebar использует Sheet, очередь и карточка располагаются последовательно.

Допущения: updated и occurred_at — Unix seconds; project — название либо объект с name/id; artifacts — список названий либо словарь артефактов. Возможность создания обозначается create или create_task в capabilities.actions. Неизвестная возможность закрывает действие. Polling выполняется каждые пять секунд при видимой странице, устаревшие ответы игнорируются. Ввод форм хранится отдельно от snapshot задачи.

Выбранная задача имеет тип number | undefined: до загрузки списка, при пустом списке или некорректном ?task=ID выбор может отсутствовать. Это штатное состояние, а не фиктивный идентификатор задачи.

Уточнение принятого плана: операторский API уже подготовлен внешним контроллером. Frontend использует same-origin /api/v1 напрямую через подставляемый типизированный транспорт. Python-адаптеры, MCP subprocess и параллельная реализация переходов не требуются: runtime wiring, HTTP-защита, сессии, static export и receipt остаются у native gateway. Исходные Python server/launcher и 15 тестов сохранены. Старую стартовую страницу нельзя удалять до подтверждённой доставки экспорта.

Start/pause/resume/answer используют CSRF, revision, идемпотентный ключ и GET операции. Создание ограничено 50 КиБ UTF-8, ответ — 16 КиБ. Успех показывается только после succeeded. Человеческие решения передаются ссылке отдельного origin через диалог; открытие не считается подтверждением. Приёмка не применяет diff. Apply и preview отсутствуют.

Уточнение по ревью: блок решений включает awaiting_approval, review, needs_* и waiting с непустым question. Это навигационная подсказка по snapshot, а не источник полномочий; действия по-прежнему определяет control.allowed_actions. Review рассматривается как ожидание человеческого решения, включая stage done.

Неопределённый POST сохраняет исходные task id, тело, revision и Idempotency-Key. Отдельная кнопка повтора доступна после обновления snapshot даже при изменении allowed_actions; допустимость повтора проверяет engine. Пока результат неизвестен, новые команды закрыты. После получения operation_id повторяется только GET операции. Однозначный HTTP-отказ 4xx, кроме 408, освобождает команду и инициирует перечитывание snapshot; сетевые ошибки, некорректный ответ и 5xx сохраняют неопределённость. Допущение: корректный error-envelope с 4xx обозначает окончательный отказ gateway. Неопределённые команды сохраняются в sessionStorage до отправки: отдельная запись для каждой задачи и отдельная для создания. Записи содержат точный payload, revision и ключ, после принятия команды — operation_id; сессионные и CSRF-токены не сохраняются. Запись переживает remount и reload той же вкладки; закрытие вкладки завершает срок хранения. Успех и окончательный отказ очищают запись. Ошибка сохранения до POST отменяет отправку. При создании исходные запрос и режим восстанавливаются; окончательные 400/422 разрешают исправить ввод и отправить новую команду с новым ключом. Допущение: один подключённый проект на операторский origin; смена проекта в той же вкладке не поддерживается.

Проверка origin, сессии, CSRF, полномочий, revision, идемпотентности и безопасной раздачи экспорта обязательна во внешнем gateway. Frontend не может заменить эту границу. Подтверждённые адреса допускаются только http://127.0.0.1:47832/confirm без userinfo и fragment, с query контроллера.

Node, npm, tsc, Vitest и Next агентом не запускаются. Контроллер должен выполнить проверки в подготовленной сборочной копии и связать receipt с исходниками, runtime, lockfile и dependency tree. До receipt сборка и независимые проверки не подтверждены.

Уточнение после ошибок проверки типов: глобальный CSS подключается статическим require в корневом layout, обрабатываемым сборщиком Next. Отдельный файл деклараций не добавляется за пределами разрешённого списка. DOM-проверки используют стандартные assertions Vitest и свойства DOM вместо несовместимого расширения Assertion из jest-dom; проверяемые условия сохранены. Зависимости и строгость TypeScript не изменяются.
