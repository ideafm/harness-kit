# Запуск, остановка и открытие результата

Пользователь подтвердил просмотр результата до приёмки и упростил первый этап:
основной сценарий — один проект, без нового менеджера портов и Docker Compose.

Использовать существующий изолированный просмотр static/подготовленного next-ui.
В карточке результата показать компактный блок с иконкой приложения, индикатором,
фактическим адресом и действиями Запустить, Остановить, Открыть в новой вкладке.
Сохранять адреса существующих проектов. Занятый чужим процессом порт не перехватывать.
Не выдавать готовность сервера за готовность выбранного результата.

После завершения задачи и независимого ревью автоматически выбирать проверенную
версию и запускать просмотр, если профиль уже настроен. Отказ просмотра сохраняется
отдельно и не останавливает очередь/не принимает результат. Ручная остановка
сохраняется на диске и запрещает следующий автоматический запуск. Явный запуск
возобновляет автоматическое обновление. Stop останавливает только просмотр.

HTTP stop проходит существующие Origin/CSRF, If-Match, Idempotency-Key и проверку
владения процессом. Повтор старой остановки не выключает новый запуск. Статус
просмотра доступен даже если рабочая копия выбранной задачи ещё не подготовлена.
Старый контроллер без stop capability не должен получать неподдерживаемые команды.

Существующие пояснения и дополнительные режимы сохраняются в свёрнутом разделе.
Использовать собственные SVG-иконки AppIcon, текстовые подписи, focus и disabled
состояния. Ошибка показывает причину; открытие допускается только по проверенной
локальной ссылке. Остановка не зависит от открытой вкладки приложения.

Команда run из tw configure остаётся сохранённой настройкой. Произвольные
Nuxt/dev-server/Compose требуют следующих адаптеров; unrestricted fallback запрещён.
