# Проекты и прогресс задач

Уточнение после ревью: project id `.` и `..` невозможно безопасно передать отдельным сегментом указанного API: браузер нормализует также percent-encoded точки. Для этих двух значений проектные GET и POST отклоняются локально с явной ошибкой без обращения к transport; общий session остаётся доступным. Подмена id, двойное кодирование и fallback на общий API исключены. Остальные непрозрачные id кодируются одним сегментом. Регрессионные тесты проверяют отсутствие запросов для опасных id и фактический адрес остальных после URL-нормализации.

Текущий этап — исполнение по прямому поручению «Реализуй план». Прежнее ограничение этапа планирования «менять только возвращаемый план» относится к прошлому этапу и не является критерием реализации. Это не отменяет прежний результат ревью и не означает приёмки TASK-002 или TASK-003. Допущение исполнения: уже присутствующая реализация сохраняется после сверки с планом; повторное создание панели не требуется.

Продолжить baseline TASK-002 без приёмки и применения. GET projects предоставляет список; session остаётся общим. Остальные запросы используют projects/{id}. Подключение выполняет человек на connect_url в отдельной странице, после возврата список обновляется.

Выбранная задача, pending, операции и компоненты изолируются по проекту. Поздние ответы не меняют новый контекст. Старые pending без проекта сохраняются без автоматической отправки. URL project/task восстанавливается только в контексте проекта; неизвестные значения показываются явно.

Каждая задача показывает: Спецификация и план → Реализация → Проверки → Ревью → Приёмка. Текущий stage определяет шаг, accepted означает человеческую приёмку, done/review — ожидание приёмки. Возвраты этапов отражаются сразу. Действия определяет только allowed_actions.

Допущения: project id — непрозрачная строка, кодируемая одним сегментом; используется sessionStorage. Старые названия этапов поддерживаются как псевдонимы. Новые зависимости и изменения backend исключены. Проверки запускает контроллер; результаты baseline не являются проверками этой задачи.

При переключении сбрасываются status, capabilities, control и выбранная задача; дерево событий и артефактов перемонтируется по project/task. Отменяются чтения и проверяется поколение ответа независимо от поддержки AbortSignal. Неизвестный явно указанный проект не заменяется основным; неизвестная задача не выбирает другую автоматически. История браузера обрабатывается через popstate.

Команды сохраняют исходные body, revision, Idempotency-Key и operation id. При уходе POST может завершиться только в исходном слоте; последующий polling прекращается. Возврат и reload не повторяют POST автоматически. Известная операция проверяется GET по явному действию. Запоздалое завершение не стирает pending с другим ключом. Общие legacy-слоты используются только прежним непроектным transport в совместимых тестах; проектный интерфейс их не читает и не меняет.

confirmation_urls сохраняют существующую проверку доверия и параметры проекта. Открытие ссылки не означает решения человека. Регистрация путей через JSON API отсутствует. Управление доступно только по актуальным allowed_actions, CSRF и revision. Не меняются loopback-only доступ, lifecycle worker, backend, launcher, зависимости и правила безопасности. Недоверенные запросы, события и артефакты выводятся текстом.

Индикатор не выводит процент и не предполагает отдельного завершённого этапа спецификации. plan объединяет исследование, спецификацию и план. Ожидания, вопрос, разрешение, лимит, пауза, ошибка, блокировка и rejected показываются рядом с текущим шагом. Неизвестные или противоречивые значения не объявляют успешного завершения. Артефакты не доказывают прохождение этапа.
