# Спецификация: Quota Guard (95% Codex и Gemini, TTL 2 мин для /quota) и штатный запуск Tw

Дата: 2026-11-08. Статус: утверждено к реализации.

---

## 1. Цель и контекст

1. Обеспечить корректную работу защитного механизма квот (`Guard` в `harness/quota.py`):
   - Установить порог остановки ровно **95.0%** отдельно для пятичасового и недельного окон как для `codex`, так и для `gemini`.
   - **Codex:** источник `account/rateLimits/read` через `codex app-server --stdio`, TTL снимка 15 секунд.
   - **Gemini:** источник `agy -p "/quota" --output-format json` с ограничением частоты опроса: **не чаще 1 раза в 2 минуты (TTL снимка 120 секунд)**.
   - Чётко разделить причины паузы:
     - При исчерпании квоты ($\ge 95\%$) задача ожидает фактического сброса: `resets_at + 60`.
     - При ошибке чтения/проверки квоты (таймаут >15с, повреждённые данные) задача получает защитную паузу до `now + 60` для повторного запроса источника. Защитная пауза сама по себе не подтверждает сброс квоты.
   - Разрешить противоречие для истёкшего `resets_at`: разграничить условия перечитывания источника, использования снимка и приостановки задачи.
   - Изолировать бэкенды: снимки хранятся в `.harness/quota-codex.json` и `.harness/quota-gemini.json`, исчерпание или сбой одного backend не блокирует задачи другого.
   - Гарантировать fail-closed поведение без списания счётчика попыток этапа (`attempts`).

2. Зафиксировать штатное подключение инструментов Tw и независимость очереди:
   - Основной сценарий: сессионный запуск `bin/tw chat` (с флагом `--settings`) и веб-панель `tw-web` как два независимых канала управления. Доступность веб-панели не является условием работы MCP.
   - Постоянная регистрация MCP через `agy mcp add` остаётся необязательной и в данной задаче не выполняется.
   - Полный запрет на прямое чтение/модификацию `~/.gemini/config`, установку файлов в домашний каталог и прямое чтение `web/.harness/state.sqlite`.
   - Задача `TASK-009` остаётся в статусе `waiting` без ответа и изменения статуса. Очередь не блокируется: независимые задачи можно ставить и выполнять в отдельных worktree.

## 2. Спецификация Quota Guard для Codex

### 2.1. Источник данных квоты Codex
- **Исполняемый файл:** путь к `codex`, определяемый через `shutil.which('codex')` или конфигурацию `.harness/config.json`.
- **Транспорт и протокол:** запуск процесса `[executable, '--no-daemon', 'app-server', '--stdio']` с взаимодействием по протоколу JSON-RPC 2.0 через standard I/O (stdio).
- **Метод:** `account/rateLimits/read`.
- **Контракт ответа:** объект `result.rateLimits`, содержащий окна `primary` (300 мин) и `secondary` (10080 мин).
- **Кэширование (TTL):** снимок квоты сохраняется в памяти и в `.harness/quota-codex.json` с TTL = 120 секунд (как у Gemini). Фоновый polling-цикл отсутствует; опрос выполняется строго по требованию при вызове `Guard.check`.

### 2.2. Семантика окон и порог остановки 95%
1. **Пятичасовое окно (`primary`, `window_minutes == 300`):**
   - Скользящее окно потребления за последние 5 часов.
   - Порог остановки: ровно **95.0%**.
2. **Недельное окно (`secondary`, `window_minutes == 10080`):**
   - Скользящее недельное окно тарифа.
   - Порог остановки: ровно **95.0%**.
3. **Политика пользователя (`quota-policy.json`):**
   - Допустимый диапазон пользовательского порога расширяется до 95.0% (`0 < cap <= 95`).
   - Дефолтное значение — 95.0%.

## 3. Спецификация Quota Guard для Gemini

### 3.1. Источник данных квоты Gemini
- **Исполняемый файл:** путь к `agy`, определяемый через `shutil.which('agy')` или конфигурацию `.harness/config.json`.
- **Команда:** `[executable, '-p', '/quota', '--output-format', 'json']`.
- **Таймаут выполнения:** 15 секунд.
- **Ограничение частоты опроса (TTL):**
  - Опрос выполняется **не чаще 1 раза в 2 минуты (TTL = 120 секунд)**.
  - При наличии валидного снимка в `.harness/quota-gemini.json` (возраст $\le 120$ с и `resets_at > now`) вызов `agy -p` не производится.

### 3.2. Нормализация данных Gemini
- Извлекается группа `Gemini Models` из `result["command"]["data"]["groups"]`.
- Поле `reset_time` обязано содержать явный часовой пояс (например, суффикс `Z` или смещение `+HH:MM` / `-HH:MM`). Строки без часового пояса (naive) отклоняются ошибкой валидации, чтобы время сброса не зависело от локальной временной зоны машины.
- Для корзины с `window == "5h"` (`gemini-5h`):
  - `window_minutes = 300`.
  - `used_percent = round((1.0 - bucket["remaining_fraction"]) * 100.0, 2)`.
  - `resets_at = int(datetime.fromisoformat(bucket["reset_time"].replace('Z', '+00:00')).timestamp())`.
  - Порог остановки: ровно **95.0%**.
- Для корзины с `window == "weekly"` (`gemini-weekly`):
  - `window_minutes = 10080`.
  - `used_percent = round((1.0 - bucket["remaining_fraction"]) * 100.0, 2)`.
  - `resets_at = int(datetime.fromisoformat(bucket["reset_time"].replace('Z', '+00:00')).timestamp())`.
  - Порог остановки: ровно **95.0%**.

## 4. Разделение причин паузы и жизненный цикл снимка

### 4.1. Разделение причин паузы
1. **Штатная пауза по исчерпанию квоты (`used_percent >= 95.0%`):**
   - Возникает, если `used_percent >= 95.0` в окне 300 мин или 10080 мин при `resets_at > now`.
   - Действие: `QuotaPause(f"Защитная пауза: использовано {used}% лимита {backend}; порог 95%", resets_at + 60)`.
   - Задача переходит в `rate_limited` и ожидает фактического сброса окном провайдера.
2. **Защитная пауза при ошибке чтения/проверки квоты (fail-closed):**
   - Возникает при таймауте (>15с), ошибке запуска процесса, ненулевом коде возврата или повреждённом JSON.
   - Действие: `QuotaPause(f"Не удалось проверить лимит {backend}; новые вызовы запрещены", now + 60)`.
   - Задача получает паузу до `now + 60`.
   - **Важное правило:** защитная пауза `now + 60` сама по себе **НЕ подтверждает сброс квоты**. При возобновлении Guard обязан повторно запросить источник.
   - Счётчик попыток этапа (`attempts`) не расходуется.

### 4.2. Истёкший `resets_at` и перечитывание источника
1. Снимок валиден, только если:
   - Для обоих бэкендов (Codex и Gemini): `(now - snapshot["observed_at"]) < 120` секунд (TTL = 120 с).
   - Для всех окон в снимке: `snapshot["resets_at"] > now`.
2. Если `(now - snapshot["observed_at"]) >= 120` секунд или `snapshot["resets_at"] <= now` (лимитное окно роллировалось), снимок инвалидируется, задача **не приостанавливается**, а Guard производит немедленный свежий опрос источника.
3. Фоновый polling-цикл отсутствует: опрос источника происходит строго по требованию в момент вызова `Guard.check()`.

## 5. Штатный запуск Tw и независимость очереди

1. **Сессионный запуск `tw chat`:**
   - Основной способ работы оператора с MCP: `bin/tw chat --backend=gemini`, передающий `--settings` с изолированной конфигурацией `mcpServers: {"tw": ...}`.
   - Глобальные файлы профиля `~/.gemini/` не читаются и не модифицируются.
2. **Панель `tw-web`:**
   - Работает независимо на [http://127.0.0.1:47831](http://127.0.0.1:47831).
3. **Состояние `TASK-009` и очередь:**
   - `TASK-009` остаётся в статусе `waiting` (проверено штатной командой `bin/tw show TASK-009`).
   - Новые независимые задачи могут ставиться в очередь и выполняться в изолированных рабочих копиях (`tw/TASK-xxx`) без закрытия `TASK-009`.
