# Рабочие копии, live-preview и коммит после приёмки

Пользователь разрешил сейчас сохранить всё текущее как initial. Далее каждая
принятая задача получает отдельный коммит. До приёмки работа остаётся без
коммита, доступна в изолированной рабочей копии и в предпросмотре. Автоматического
merge в основную ветку без отдельного правила нет.

Initial сохраняет видимые исходники и документы двух текущих репозиториев,
без env, ключей, скрытых пользовательских файлов и controller/runtime state.
Принятый TASK-003 интегрируется проверяемой операцией с защитой чужих правок.

Worktree принадлежит контроллеру и создаётся без автоматического checkout
защищённых файлов. Агент получает только разрешённые видимые исходники;
Git-метаданные, индекс и git-операции ему не передаются. Коммит фиксирует
точный принятый результат; существующие пользовательские изменения не смешиваются.
Сохраняются branch/base, receipt, hash tree, commit и связь с задачей.

Preview доступен до приёмки и во время реализации по отдельному loopback origin.
Первый поддерживаемый runtime — существующий подготовленный Next toolchain:
контроллер собирает стабильный снимок в прежнем проверенном sandbox с закрытой
сетью, затем раздаёт только manifest статического export. Платные вызовы для
обновлений preview не нужны. Source changes автоматически вызывают пересборку;
при ошибке показывается её статус и последняя успешная версия, не фиктивный успех.
Предпросмотр не получает CSRF/приёмку/изменяющие API. Для панели допустим только
read-only GET gateway данных; POST и операторские решения запрещены.

Проверки preview хранятся отдельно и не перезаписывают receipt/check.log текущего
этапа. Итоговая приёмка по-прежнему требует независимых проверок результата.
Неподдерживаемый runtime возвращает понятную причину, без unrestricted fallback.
Для других проектов механизм выбирается по подключённому runtime, а не запускает
произвольный shell или env-файлы. Команда preview содержит project/task.
