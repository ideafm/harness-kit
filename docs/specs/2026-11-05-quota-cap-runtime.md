# Порог лимита и сохранённый Node runtime

Пользователь уточнил: остановиться и сделать паузу при 50% только пятичасового
лимита; недельное окно 67% не является этим условием. Продолжение до 50%
явно разрешено после уточнения. Это контрольная точка для сверки прогресса,
а не техническая блокировка. При пороге сохранять этап/попытки, state paused,
без retry_at и автоматического продолжения. Порог задаётся в доверенном
.harness/quota-policy.json, проверяется и при старте, и во время выполнения.
Прочие существующие защитные ограничения остаются. При недоступности данных
новые вызовы запрещены.

Проверки frontend сейчас блокируются после обновления Homebrew: абсолютного
пути исходного Node больше нет. При этом ранее подготовленный автономный
runtime Tw сохранён. Проверка должна использовать его фиксированное размещение
в состоянии контроллера и сверять полный хеш runtime и зависимостей с receipt.
Удаление исходного Homebrew binary не является изменением сохранённого runtime.
Не подменять версию Node текущей системной, не обновлять зависимости и не
пропускать canary. Подмена путей/ссылки/изменение файлов блокируют исполнение.
