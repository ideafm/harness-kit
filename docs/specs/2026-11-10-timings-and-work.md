# Реальное время этапов и «В работу»

Времена вычисляются контроллером по журналу stage_started/stage_finished/checks_finished, включая повторные попытки. Паузы, вопросы и ожидание лимитов не считаются выполнением. Текущий этап обновляется с обычным polling. Нет достоверного измерения — «—», не демонстрационная длительность. Ожидание приёмки учитывается отдельно.

Для backlog добавляется обычное идемпотентное действие enqueue с подписью «В работу»: задача ставится в конец существующей очереди, worker запускается при необходимости. Другие состояния сохраняют прежние действия и ограничения. Текущий порядок групповой очереди не меняется.

Ночной режим — отдельный будущий этап. Вопрос/ошибка/конфликт блокируют только задачу; независимые задачи продолжаются. Явные depends_on при постановке, проверка циклов и принадлежности проекту. Зависимые ждут успешно применённого результата предпосылки, а не только окончания её выполнения. Автопринятие включается отдельно, не активируется этим изменением.
