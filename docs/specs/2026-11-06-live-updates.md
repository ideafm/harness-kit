# Обновления через SSE

GET /api/v1/projects/{project_id}/stream (и stream текущего проекта) —
read-only поток уведомлений об изменении состояния. Существующая проверка
Host/Origin и реестра проектов обязательна. Поток не запускает worker.
Только операторская панель объявляет capabilities.stream=true;
предпросмотр не открывает операторский поток.

События sync при каждом подключении и changed при изменении означают:
перечитать актуальные GET status/control/view, сохранив уже показанные данные.
Это invalidation, не транспорт сырых логов и не обещание replay истории.
Last-Event-ID принимается, но после reconnect всегда нужна полная сверка GET.
Формат text/event-stream, UTF-8, id/event/data/retry, heartbeat-комментарии.

Не более 16 соединений на экземпляр панели; медленный клиент не блокирует
команды и других клиентов. Таймаут записи, закрытие при shutdown, disconnect
и смене экземпляра проекта. Наблюдать SQLite data_version и строго заданные
файлы состояния runtime/worker/quota/registry; не читать рабочие исходники,
env или скрытые пользовательские ресурсы. Модель для наблюдения не вызывается.

UI подключается отдельной задачей Tw после TASK-008: один EventSource на
выбранный проект, cleanup при смене проекта/unmount, защита от старых ответов,
объединение частых уведомлений. Никаких моргающих loading при обновлении;
фокус, прокрутка, раскрытия и черновики сохраняются. При потере связи показывать
спокойный индикатор; reconnect вызывает sync. Старый polling допустим лишь
как fallback при отсутствии stream capability.

Источник формата: Context7 /mdn/content, Using server-sent events.
