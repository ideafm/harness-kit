# Профили исполнения: качество прежде расхода

Новые проекты получают auto-balanced; существующие проекты и задачи без профиля
сохраняют прежние настройки. В форме задачи: профиль проекта, auto-balanced,
усиленный план/ревью, ручной режим прежнего агента. Отдельный выбор исполнителя
реализации Codex/Gemini. Снимок выбранной политики сохраняется при создании задачи.
Модель — пара backend/model; GPT model IDs не попадают в Gemini.

Auto-balanced: обычный план Sol, реализация Sol либо Gemini (его явно настроенная
модель), независимое ревью Sol. Если план выявил риск/сложность/критические файлы,
обязательное перепланирование Astra до публикации плана/реализации; ревью Astra.
Усиленный профиль: Astra планирует и ревьюит, Sol/Gemini реализует. Luna не
используется по умолчанию: качество приоритетно. После двух неуспешных реализаций
исполнитель повышается до Sol (если был Gemini), затем Astra; возврата к более
слабой модели в рамках задачи нет. Исходная причина и каждая смена фиксируются.
Тесты, независимое ревью, человеческие решения и изоляция не ослабляются.

В UI показать фактический маршрут и причины повышения. Недоступная модель или
исчерпанный лимит не разрешают молча снизить качество. Точная экономия ещё не
измерена, проценты не обещать. Входные stage overrides/model считаются ручной
настройкой и не смешиваются неявно с автоматической политикой.

CLI/MCP/API принимают профиль задачи. tw configure --execution-profile меняет
профиль только для новых задач. Новые tw init автоматически сохраняют auto-balanced.
Обновить проверенную панель и коммитить по действующему поручению пользователя.
