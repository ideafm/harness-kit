# Бэклог и запуск выбранной группы — основа

Задача placement=backlog хранится в отдельном состоянии backlog и никогда
не подхватывается worker. placement=queue сохраняет прежнее поведение.
Флаг start управляет запуском процесса worker и не заменяет placement:
уже работающий worker имеет право взять queued, но не backlog.
CLI add --backlog, MCP tw_submit placement=backlog и POST tasks с placement
поддерживают создание без старта. Отсутствующее поле сохраняет совместимость.

Явная операция enqueue переводит выбранные backlog/queued в очередь в заданном
порядке одной транзакцией. Неверная, повторённая, выполняющаяся или завершённая
задача отклоняет всю группу. Существующие задания вне группы остаются перед ней.
Сохранять queue_order в контроллерном состоянии, старые queued сортировать
по прежнему id. CLI enqueue [--start] и MCP tw_enqueue используют общую
операцию; HTTP группа имеет CSRF, Idempotency-Key и If-Match версии списка.
После restart порядок сохраняется; один worker продолжает брать по одной.

В этой части нет UI группового выбора, зависимостей или автоприёмки.
Их подключать следующими проверяемыми этапами. Обсуждение не вызывает enqueue.
