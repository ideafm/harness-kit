# Продолжение результата и контроль лимита

Пользователь поручил продолжить TASK-003 без рутинного согласования и следить
за пятичасовым лимитом: при 96% пауза, продолжение после сброса; предпочтительнее
остановиться заранее. Проверенное значение через /status: около 80% использовано,
сброс 22:24 Europe/Moscow. Это наблюдение, не постоянная величина.

Контроллер может передать TASK-003 проверенный результат TASK-002 как входную
основу, без приёмки, коммитов и применения в исходный проект. Только завершённый
проверенный результат того же проекта. Источник проверяется по check receipt
и manifest, frontend также по source_digest. Целевая задача должна быть на
планировании, без локальных правок; замена не исполняет агентский код.

Сохраняются исходная копия, отдельный baseline и копия для агента. Baseline
не виден агенту, не содержит ссылок или защищённых файлов. Он записывается
в состоянии целевой задачи с ID источника и хэшами. Дальнейший diff считается
от baseline; ревью явно получает происхождение. Повреждение baseline блокирует
проверки. Частичная подготовка блокирует повтор, автоматического fallback нет.

Лимиты получать через поддерживаемый интерфейс Codex без чтения credentials.
Перед новыми платными этапами проверять расход; пауза с запасом до 96%,
неизвестное/устаревшее значение при включённом guard блокирует новые вызовы.
Сохранённое ожидание должно переживать перезапуск; просроченные сведения не
считать свидетельством сброса. После reset нужна свежая проверка.

Реализованный запас: новый этап не стартует при >=90% пятичасового лимита;
активный процесс проверяется каждые 15 секунд и прерывается при >=94%.
Ожидание сохраняется как rate_limited до resetsAt+60, после чего guard требует
свежий ответ. Неизвестный лимит даёт ожидание 60 секунд, без платного вызова.
Это контроль runner, а не глобальный запрет запросов во всех сессиях аккаунта.
В корневой сессии расход проверяется отдельно; другие запуски тоже учитываются
в показании аккаунта. Настройка включается явно quota_guard=true в конфигурации
контроллера; она включена для tw-web. Данные quota.json содержат только расход,
окно, время сброса и наблюдения. Учетные данные/профиль не сохраняются.
Источник протокола: https://learn.chatgpt.com/docs/app-server
(account/rateLimits/read, usedPercent, windowDurationMins, resetsAt).
