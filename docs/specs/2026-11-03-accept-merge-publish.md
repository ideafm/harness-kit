# Приёмка, merge и активация результата

Пользователь явно разрешил новый сценарий: агент меняет рабочую копию проекта,
пользователь смотрит live-результат; «Принять» создаёт коммит и сливает его в
основную ветку, обновляет доступный результат. «Доработать» продолжает ту же
рабочую копию; «Отклонить» исключает её из активного просмотра и сохраняет
основную принятую версию. Исходный запрос/история сохраняются. Это разрешение merge
принятых результатов, не доступ к защищённым файлам и не force-reset чужих правок.

Интеграция требует accepted, успешного receipt, точного commit результата,
заданной основной ветки и чистого исходного дерева. Merge выполняет контроллер
без hooks/signing/сети. Конфликт безопасно abort, результат остаётся accepted
с явным integration_error, а не фиктивным «применено». Повтор идемпотентен.
Начальный существующий конфликт README TASK-004 разрешить сохранением initial
README в docs/history, актуальный README взять из принятого результата.

Для текущей панели активация использует проверенный статический export задачи.
web-ui metadata переключается атомарно, сервер подхватывает новый manifest при
следующей загрузке страницы. Приёмка сообщает про применение и активацию.
Для сторонних runtime — обновление основной рабочей копии и поддерживаемого
preview, без запуска произвольных команд или чужих процессов. Preview сохраняет
отдельный origin; единый UI может встраивать его только с подходящей CSP.

«Отклонить» не удаляет незакоммиченные пользовательские файлы и историю: агентская
копия остаётся для диагностики, выбранной становится последняя принятая версия.
Откат внешних действий/данных не подразумевается.
