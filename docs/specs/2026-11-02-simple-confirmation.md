# Простое подтверждение результата

Исправить ошибку «Недопустимый адрес запроса» при подтверждении. Не ослаблять
проверку Origin у изменяющих запросов. У страниц форм использовать
Referrer-Policy: same-origin вместо no-referrer: последняя может превращать
Origin POST-формы в null. localhost при GET направлять на канонический
127.0.0.1; произвольные Host и Origin запрещены.

Приёмка результата и утверждение плана: страница с проектом, задачей и одной
явной кнопкой. Номер задачи передаёт нажатая кнопка, ручной ввод не нужен.
Возврат на доработку требует замечаний; окончательное отклонение сохраняет
ручное подтверждение номера. GET ничего не меняет; токен одноразовый,
версия/revision проверяются; подтверждение остаётся в доверенном контроллере.

## Уточнение пользователя: действие внутри карточки

Отдельная страница или вкладка подтверждения больше не соответствует запросу.
В карточке задачи пользователь нажимает «Принять» один раз и видит результат
там же. Frontend не получает полномочие программно принимать результат.
Предпочтительное решение: встроенная форма доверенного контроллера в iframe
другого origin. Нажатие кнопки внутри этой формы отправляет одноразовый токен;
результат показывается в той же области, панель обновляет status/control.
Только выделенный маршрут встроенной формы допускает frame-ancestors точного
origin панели. Остальные страницы сохраняют запрет встраивания. Привязка
проекта, задачи, версии и revision обязательна; GET не меняет состояние.
Не заменять это обычным JSON endpoint с human=true из агентского frontend.

Видимость работы: карточка показывает текущий этап и причину ожидания, вкладка
«События» — реальные события контроллера с временем, вкладки документов —
сохранённые spec/plan/diff/checks/review. До сохранения явно показывать
«ещё не готово»; старый план во время пересмотра помечать предыдущей версией.
Текст событий и документов выводится как недоверенный текст. Текущий API
не передаёт поток рассуждений или live-preview приложения; не имитировать их.
