# Автоматически применять результаты

Проектная настройка по умолчанию выключена. Изменение только через separate-origin trusted form с одноразовым токеном, сроком, project id и revision; GET не меняет политику, обычный API не включает её. Каждый переход политики создаёт новое поколение. Задача фиксирует поколение при первом запуске, повторный запуск старой задачи/готового результата не выдаёт новых прав. Выключение запрещает новые автоматические приёмки; уже принятую контроллером интеграцию разрешает завершить.

Готовый результат autoeligible только при совпадении актуального включённого поколения, отсутствии manual_acceptance, low/small плане, pass свежего ревью и совпадении результата с receipt успешных проверок. Контроллер повторно проверяет документы/изменения и CAS-переходом записывает accepted_by=automatic. Git commit/merge и объединённая проверенная публикация используют существующий integration path. Ошибка фиксируется в задаче без остановки независимой очереди. Незавершённая после перезапуска интеграция восстанавливается идемпотентно; записанная ошибка требует человека и не повторяется бесконечно.

Manual_acceptance задаётся при создании; подпись «Обязательно показать мне перед применением». Результат показывает «Применено автоматически» либо «Принято пользователем» по источнику приёмки. Старые задачи без источника не получают выдуманный источник.

Зависимости и ночное расписание в этот этап не входят; независимые задачи продолжаются по действующему scheduler. Автоприменение не включает автоматическое утверждение плана и не расширяет sandbox/доступ. Для harness/controller/security изменений действует ручная приёмка.
