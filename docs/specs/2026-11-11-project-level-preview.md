# Перенос управления запуском приложения на уровень проекта

## Цель

Перенести управление запуском приложения (preview) с уровня отдельной карточки задачи на уровень проекта в верхней части панели.
Обеспечить доступность статуса и управления независимо от выбранной карточки задачи и корректное переключение между проектами.

## Требования к интерфейсу

1. В верхней части панели рядом с названием выбранного проекта размещается компактный блок предпросмотра:
   - Статус: «Остановлен», «Запускается», «Запущен» или «Ошибка» с цветным индикатором.
   - Кнопки с иконками и текстом: «Запустить», «Остановить», «Открыть».
   - Фактический адрес запущенного приложения (например, `127.0.0.1:40001`).
   - Подпись активного результата: например, `TASK-012 · проверенная версия`, `TASK-012 · рабочая версия` или `Версия не выбрана`.
2. «Открыть» открывает приложение в новой вкладке (`target="_blank"`, `rel="noopener noreferrer"`) и доступна только после подтверждения готовности результата (`viewReady` с проверкой согласованности ревизий, digest и задачи).
3. Статус и управление доступны независимо от выбранной карточки задачи. При смене проекта отображается состояние выбранного проекта.
4. В карточке задачи:
   - Сохраняется действие «Показать результат этой задачи» (переключает активный результат проекта на данную задачу).
   - Сохраняется выбор проверенной или рабочей версии с существующими пояснениями.
   - Убираются дублирующие общие кнопки запуска, остановки и открытия.
5. Адаптивность и стили:
   - Поддержка светлой и тёмной темы.
   - Аккуратные состояния загрузки, ошибки и disabled.
   - Кнопки и подписи помещаются при узкой ширине экрана.

## Поведение кнопки «Запустить» без выбранной версии

Если для проекта ещё не выбрана версия (`view.selection() is None`) или нет готовых результатов:
- Подпись отображает: `Версия не выбрана`.
- Кнопка «Запустить» находится в состоянии `disabled` с подсказкой «Сначала выберите результат в карточке задачи». Произвольная задача молча не выбирается.
- Если версия уже выбрана (сохранена в `selection.json`), кнопка «Запустить» запускает dev-server с этой версией.

## Технические требования и архитектура

1. Backend:
   - Минимальный проектный API в `ViewControl` и `harness/web.py`:
     - `GET /api/v1/view` (и `GET /api/v1/projects/<id>/view`): возвращает статус проекта, текущий выбор, ревизию и доступные действия.
     - `POST /api/v1/view`: выполняет действия `stop` или `select`/`refresh` для текущей выбранной версии с проверками If-Match, Idempotency-Key, CSRF и Origin.
   - `ProjectView.control_revision(ident=None)`: поддерживает вычисление проектной ревизии без привязки к конкретной задаче.
   - Существующие эндпоинты `tasks/<id>/view` сохраняются для совместимости.

2. Frontend:
   - Обновление `useProjectView`: поддержка запросов без номера задачи (на уровне проекта `tasks/${task}/view` vs `view`).
   - Компонент `ProjectPreviewBar` в верхней панели: компактный вид, состояния, кнопки, открытие проверенного URL.
   - Очистка `ProjectView` в карточке задачи: сохранение «Показать результат этой задачи» и подробностей без дублирования общих кнопок.

3. Безопасность:
   - Защита от устаревших ответов при смене проекта (scope key, AbortController, sequence).
   - Сохранение ручной остановки (`manually_stopped`).
   - Изоляция процессов и распределение портов не изменяются.
