# Этап 1: desktop-редизайн «Фокус»

База: tw-web main с принятой TASK-005. Реализация новой задачей Tw, старые
задачи не возобновлять. Сохранить спецификацию, план и сводку до исполнения.
Пользователь разрешил этап без рутинного согласования; это не приёмка результата.

## Внешний вид

Точный референс — docs/designs/tw-research-2026-11-05/index.html, вариант 01.
Контроллер передаёт его как design_reference до запуска. Убрать лабораторную
полосу выбора вариантов и сценариев. Основной экран desktop; отдельную мобильную
версию не развивать. Светлая сине-серая палитра, проекты слева около 196px,
компактная очередь около 300px рядом, выбранная задача в основной карточке.
Breadcrumb/topbar, типографика, отступы и разделители по референсу.
Этапы точками с hover/focus-подробностями, реальные статусы и главное действие
в контексте причины. Материалы и технические подробности во вкладках/раскрытии.
Сохранить shadcn и собственные компактные иконки, без стандартного набора.

## Сохранность функций

Сохранить реестр, подключение и переключение проектов, URL project/task,
постановку задач, очередь, worker и watch-команду, полный исходный запрос,
артефакты, события, вопросы/причины остановки, polling/свежесть/ошибки,
readonly, trusted iframe и три действия приёмки, preview, достоверные
accepted/integration/error статусы TASK-005. Сохранить изоляцию проектов,
защиту от запоздалых ответов и идемпотентность. Не дублировать state transitions.

Никаких фиктивных задач, процентов, лимитов, серверов/БД, обсуждений без API.
Возможности этапа 2 честно обозначать недоступными либо не показывать:
общие обсуждения, профили окружений, независимые БД и параллельность не должны
задерживать редизайн.

## Документация и проверки

Документация получена через Context7 /shadcn-ui/ui (github.com/shadcn-ui/ui):
SidebarProvider оборачивает Sidebar, управляется open/onOpenChange;
ширины --sidebar-width и --sidebar-width-mobile задаются через style.
Сохранять доступные подписи и клавиатурное взаимодействие. Использовать
существующие компоненты без новых зависимостей.

Реализация только в изолированном workspace Tw. Не менять исходную main,
соседний harness-kit и работающий контроллер. Не читать скрытые пути, env,
секреты и ключи, не использовать SSH, не обходить sandbox. Не выполнять
commit/merge/accept самостоятельно. Интерфейс и документация на русском,
без новых кодовых комментариев.

Через контроллерный next-ui toolchain выполнить frontend tests, TypeScript,
production build и python3 -m unittest discover -s tests -v. Добавить
сценарные проверки регрессии поведения, не проверки CSS-классов.
Результат оставить на человеческой приёмке. Browser QA делает корневой
оператор на preview; недоступные проверки явно отмечать.
