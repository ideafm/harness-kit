# Упрощение приёмки и просмотра — предложение по итогам двух ревью

Статус: реализация по поручению пользователя после обсуждения.

Карточка review/done: «Готово к приёмке», короткая фактическая сводка, «Посмотреть результат», три действия «Принять», «Доработать», «Отклонить». Принять — один настоящий клик в компактной trusted форме контроллера, без дополнительного подтверждения. Доработать — модалка с обязательными замечаниями. Отклонить — модалка с необязательным замечанием; контроллер подставляет нейтральную причину при пустом тексте, номер задачи передаётся скрыто.

Черновики trusted iframe остаются смонтированными при закрытии модалки. Смена task/project/revision отзывает старую форму как сейчас. Родительский React не отправляет high actions и не имитирует клик по iframe. Сохраняются separate origin, одноразовый token, origin/source/project/task/revision проверки, blocked/inert на сбое связи.

Просмотр: один основной путь к проверенному результату выбранной задачи. Подготовка — явно обозначенное состояние; до готовности не открывать старую другую задачу. Непроверенная рабочая версия, повтор подготовки, last-good другой задачи и все хэши/ревизии — под «Другие варианты просмотра»/«Технические подробности». Не представлять выбранный snapshot старой задачи текущей основной версией.

После результата: «Применено» либо честное «Принято, применение не завершено» с одной причиной; не показывать лишние подтверждения и старые действия. Удаление/ветка/Git данные — второстепенные подробности. Удалить недостоверные утверждения об ESLint, контейнере, синхронизации артефактов и о принятии до фактического решения.

Следующий этап: узкая реализация и browser QA сценариев accept, request changes, reject, закрытие/повторное открытие модалки без потери текста, ошибка/подготовка/готовность просмотра.
