# Управление постоянным просмотром из панели

Сначала исправить контроллерный контракт, затем подключить интерфейс задачей Tw.
GET tasks/{id}/view возвращает доступность, конкретную причину, текущий выбор,
состояние сервера и revision. POST туда принимает select/refresh, working/checked,
If-Match и Idempotency-Key через существующую Origin/CSRF защиту.
Верхний revision является токеном If-Match, не идентификатором сборки.
view.requested.revision — UUID выбора; view.revision опубликованной версии
равен UUID:source_digest. Эти три поля имеют разное назначение. Готовность
проверяется по running/current, задаче/режиму и согласованности published
с requested/source_digest. Task.preview.version должен соответствовать
source_digest, а ссылка остаётся привязанной к задаче и этой версии.
Операция сохраняется в стандартной истории operations, не запускает worker,
не принимает результат и не меняет основную ветку. Повтор после сбоя не
переключает просмотр обратно поверх более нового пользовательского выбора.

Существующий task.preview выдаёт постоянный URL только для подтверждённо
работающего просмотра этой задачи. URL содержит task и source_digest;
устаревшая ссылка не может молча показать другую задачу или версию.
GET и read-only приложение не имеют полномочий запуска просмотра.
Старые отдельные preview сохраняются до явной миграции, чужие процессы
не останавливать. Не добавлять Docker или сетевые разрешения в этой части.

Проверки: две задачи на одном адресе, stale URL, CSRF, readonly, scope проекта,
If-Match, конфликт ключа, повтор/restart операции и сохранение нового выбора.
