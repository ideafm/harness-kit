# Исполнитель бэклога: набор → исполнение → приёмка

**Цель:** набрать задачи из `docs/backlog/`, запустить и уйти (на час или на ночь), а потом принять результат по карточкам. Решения человек принимает до запуска и при приёмке, исполнение идёт без него.

**Результат:**

- `scripts/run.sh` — исполнитель: цикл по очереди задач, на каждую свежий `claude -p` со своим контекстом.
- `/tw:run` — команда набора: бэклог с чекбоксами, подготовка входящих задач, запуск исполнителя.
- `/tw:accept` — выбор вариантами вместо ответа словами, приёмка задач из бэклога.

**Готово, когда:**

- `/tw:run` показывает задачи бэклога вариантами с множественным выбором (P0–P1 и свежие первыми, до 16); выбранные `готова` встают в очередь `.claude/tw-state/queue`, выбранные `входящая` по одной проходят `tw:spec` → `tw:plan` с человеком и после «да» становятся `готова`.
- `/tw:run` спрашивает режим (сейчас в фоне / до N задач) и запускает `scripts/run.sh` в фоне, печатает, где смотреть ход.
- Исполнитель работает в основной папке проекта, задачи строго по одной; перед стартом проверяет, что рабочее дерево чистое, иначе не стартует.
- Каждая задача: ветка `tw/B-NNN` от `main`, статус `в работе`, свежий `claude -p` с её планом; Stop-конвейер (check → scope → проверяющий) работает как в обычной сессии; после зелёного и «да» проверяющего — коммит в ветку, статус `на приёмке`, возврат на `main`.
- Задача застряла (Stop отдал человеку, проверяющий «нет» после доработки, сбой окружения) — незакоммиченное сохраняется коммитом `wip` в ту же ветку, статус `застряла: <причина>`, исполнитель берёт следующую. Два сбоя окружения подряд — останавливает весь прогон.
- Лимиты: исполнитель читает `rate_limit_event` из `stream-json`; при `five_hour` ≥ 95 % новую задачу не берёт и ждёт до `resetsAt` + 60 с. Ошибка лимита посреди задачи — та же пауза и повтор задачи.
- Каждая смена статуса — строка в журнале задачи; итог прогона — `.claude/tw-state/run.log` и строка в `/tw:status` (сделано / застряло / ждёт приёмки).
- `/tw:accept` без аргумента показывает задачи `на приёмке` списком; по выбранной — карточка (вердикты, «на тебе», diff ветки против `main`, журнал) и варианты: принять и слить в `main` / доработать (комментарий в журнал, статус `готова`) / посмотреть UI (команда запуска из ветки, вопрос повторяется) / отклонить (статус `отклонена: <почему>`, ветка остаётся).
- Прогон проверен на `~/tutor-saas` на двух реальных задачах S из бэклога, одна из них специально застревает.

**Не трогаем:** `hooks/guard.sh`, `hooks/scope.sh`, `hooks/verify.sh`.

**Не цель:** параллельные субагенты и worktree (шаг 10: тогда — worktree на субагента); денежный лимит на задачу; запуск по расписанию (cron); слияние в `main` без человека; деплой.

**Входные данные:** формат `docs/backlog/B-NNN.md` (`tw:task`), Stop-конвейер, `rate_limit_event` в `stream-json` (проверено: `five_hour.utilization`, `resetsAt`), карточка `scripts/accept.sh`.

**Допущения:**

- Коммит в свою ветку `tw/B-NNN` без «да» человека разрешён; в `main` — только через `/tw:accept`.
- Ветки от `main`; конфликт при слиянии решает `/tw:accept` (предлагает rebase) — `[допущение]`.
- Денежного лимита нет: держат лимиты подписки и круги Stop.
- `claude -p` исполнителя запускается с `--permission-mode acceptEdits` и разрешёнными командами проекта из `tw.json` (`runAllow`), без `bypassPermissions` — `[допущение]`.
- Чекбоксы — `AskUserQuestion` с `multiSelect`; задачи сверх 16 добираются словами — `[допущение]`.
