# tw-web: запуск и разработка через harness

**Статус:** реализация каркаса.

tw-web — локальная панель управления Tw и отдельный проект для проверки
самого harness на реальных задачах. Контроллер остаётся в `../harness-kit`.
Переименован из Web Harness по решению пользователя 2026-11-02.

## Первый проход

Каркас содержит Python HTTP-сервер, статическую стартовую страницу, launcher
`bin/tw-web` и проверки на стандартной библиотеке. Зависимости не ставятся.
Команда без аргументов запускает фоновый сервер при необходимости и открывает
браузер. Повторный запуск открывает тот же экземпляр. `status` показывает
состояние; `stop` останавливает только сервер панели. Worker от него независим.
Автозапуск при входе в систему не настраивается.

Сервер слушает только 127.0.0.1 на выделенном порту 47831.
Если порт занят, запуск завершается ошибкой без подбора другого порта. Runtime-файлы
живут в `.tw-web/`. Блокировка принадлежит процессу сервера; launcher
сериализует запуски отдельной блокировкой. Health проверяет идентификатор
экземпляра и проект; один PID не доказывает принадлежность сервера. Остановка
идёт через локальный защищённый endpoint, без kill произвольного PID.
При ошибке проверки существующего сервера запуск не обходит блокировку.

Host и Origin проверяются; управляющий запрос требует instance token в
заголовке и JSON. У внешних страниц нет CORS-доступа. Произвольные пути,
команды, чтение файлов и выдача разрешений не доступны через HTTP.

## Развитие через harness

Пользователь разрешил исходный Git-коммит только tw-web 2026-11-02. Это требование AGENTS.md, а не согласование плана.
Затем `tw init` подключает проект, а первая задача добавляет читающую панель
через `TaskService`. В задаче нельзя менять соседний контроллер. Ошибки ядра
фиксируются отдельно, воспроизводятся и исправляются в harness-kit.

Команда check: `python3 -m unittest discover -s tests -v`.
Внутри sandbox тесты проверяют маршрутизацию и lifecycle с подставленным
транспортом, без открытия сокетов. HTTP smoke выполняется контроллером снаружи
agent sandbox на локальном безопасном экземпляре; права worker не расширяются.
Browser QA требует отдельного разрешения согласно AGENTS.md проекта.

Результаты задач остаются на приёмке. Автоматическое применение, коммиты,
обновление работающего контроллера и публикация не входят в этот проход.
