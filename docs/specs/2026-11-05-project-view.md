# Этап 2.2a: постоянный просмотр проекта

Один loopback-адрес проекта и один процесс просмотра вместо обязательного
сервера на каждую задачу. Наблюдаемая задача панели и задача просмотра —
разные состояния. CLI tw profile configure --adapter static|next-ui сохраняет
доверенный профиль; tw view TASK-NNN --mode working|checked выбирает задачу.
tw view status/stop доступны независимо от worker. Неподдерживаемые адаптеры
не запускаются. Новых зависимостей и произвольных команд нет.

working собирается из текущей рабочей копии с сохранением версии источника.
checked использует неизменяемый экспорт с receipt успешных проверок, который
сохраняется контроллером; изменения workspace не подменяют checked.
Для static экспорт фиксируется после успешного check; Next использует
существующий frontend-receipt. Старый результат без доказательства проверок
не выдавать за checked. При ошибке новой сборки сохраняется прежняя версия
с явным указанием активной и запрошенной задачи, причины и устаревания.

Смена выбора во время сборки отменяет публикацию старого результата.
Коллизия порта не меняет адрес и не останавливает чужой процесс. При запуске,
остановке и восстановлении проверять владение по lock и nonce; PID недостаточен.
Состояние и профиль живут только в .harness вне workspace агента.
Preview остаётся read-only, не выдаёт CSRF или trusted widgets. Остановка
просмотра не останавливает worker и панель управления. Checks используют
отдельные временные snapshot и не переключают ручной просмотр.

Первая часть поддерживает static/Next export. Следующие части 2.2 — профили
нескольких сервисов и сетевые адаптеры после подтверждения ограничения bind,
egress, доступа к контроллеру и данным реальными canary. Широкий network=true
без проверенной сетевой границы не является допустимым fallback.

Источник по сетевым ограничениям: Context7 /openai/codex и официальная
https://learn.chatgpt.com/docs/permissions. allow_local_binding открывает
локальную сеть шире одного сервиса, доменные правила требуют активного proxy;
документация сама по себе не доказывает нужную изоляцию установленной версии.

## Чтение изменяемых исходников

При экспорте, diff, baseline и коммите читать обычные файлы через descriptor:
O_NOFOLLOW для файла и каждого изменяемого компонента пути, проверка типа
и числа жёстких ссылок через fstat. Обход каталогов также через descriptors,
без перехода по ссылкам после предварительной проверки. Скрытые/защищённые
имена не открывать. FIFO и другие специальные файлы не читать.
Подмена между перечислением и чтением должна приводить к отказу.
Копия должна совпадать с исходным digest; успешные проверки привязывать
к неизменившимся исходникам и составу diff. Это сохраняет границу доступа
при одновременной работе агента и подготовке просмотра.
