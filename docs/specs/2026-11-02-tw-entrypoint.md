# Tw: подключение проекта и рабочая сессия

**Цель:** восстановить понятный путь «зайти в проект → tw init → tw → поставить
задачу обычным языком», сохранив runtime-гварды существующего контроллера.

**Результат:** bin/tw, локальный skill tw, ограниченный stdio MCP bridge к
контроллеру. Неизвестные конфиги и глобальные настройки не перезаписываются.

**Готово, когда:**

- tw init подключает существующий Git-проект с HEAD, сохраняет AGENTS.md,
  ставит собственный skill и повторяется без потери задач.
- tw открывает настоящий Codex со skill и обязательным MCP Tw. Сессия может
  читать обычный код, но не менять исходник или читать защищённые пути.
- Задача через MCP сохраняется и запускается внешним worker; закрытие Codex
  не останавливает worker. Повторный start не создаёт второго worker.
- MCP ограничен одним проектом: нет произвольных путей, shell-команд, grants,
  приёмки или применения результата от имени человека.
- Статус и документы возвращаются через MCP; вопросы можно отвечать без
  расширения прав; приёмка остаётся явной командой оператора.
- Сессия не наследует посторонние MCP и интеграции; если это невозможно
  проверить, запуск блокируется. Нет unrestricted fallback.
- Путь с пробелами, повторный init, сохранение старых файлов, протокол MCP и
  сквозной вызов из настоящего Codex проверены.

**Не цель:** публикация плагина, веб-панель, глобальная установка без отдельного
действия пользователя, новые коммиты, доступ к секретам и сети кода проекта.

**Допущения:** первая версия подключается на Taskboard. Для нового Web Harness
нужны каркас, проверки и отдельно разрешённый исходный коммит. Обычная сессия
Codex вне launcher не считается защищённой сессией Tw.
