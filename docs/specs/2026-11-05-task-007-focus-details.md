# TASK-007 · Детали «Фокуса»

## Цель

Доработать представление TASK-006, сохранив проекты, очередь и основную карточку задачи. Основа — docs/specs/2026-11-05-task-006-focus.md и существующая реализация. Точное соответствие отсутствующему исходному макету не обещается.

## Поведение

- Явно выделить раздел «Доступные действия» вокруг существующего TaskActions. Единственный источник полномочий — control.allowed_actions. При отсутствии control показать недоступность управления, при пустом списке сохранить объяснение отсутствия действий. Не дублировать кнопки или логику команд.
- Для rate_limited показать заметный блок «Ожидает снятия лимита» с полной task.reason безопасным текстом. Если причина отсутствует или состоит из пробелов, показать «Подробности ограничения не предоставлены». Не придумывать квоты, остатки, таймеры или время восстановления.
- Расширить существующий AppIcon иконками ожидания, ограничения, паузы, ошибки и этапов без новых библиотек. Иконки сопровождать текстом; декоративные SVG скрывать от вспомогательных технологий.
- Выделить текущий этап в карточке и очереди. В большой карточке оставить подписи пяти этапов, в компактном представлении добавить текст текущего этапа. Сохранить описания при фокусе и наведении. Предыдущие этапы не считать завершёнными, процент из номера этапа не вычислять.
- Сохранить фактические статусы приёмки, применения, ошибок коммита и интеграции. Неизвестные сочетания stage/state показывать явно без вымышленного прогресса. Возврат этапа не накапливает отметки завершения.
- Подсказки учитывают фактический вопрос, ограничение и полномочия. Отсутствие полномочий не должно сопровождаться предложением утвердить план.
- Сохранить поиск, фильтры, страницы, выбор проекта и задачи, материалы, worker/watch, клавиатурную навигацию и узкий экран.

## Границы

Меняется только представление и перечисленные тесты и документы. Контракты, transport, useTaskData, TaskActions, TrustedDecisionWidget, сервер и контроллер сохраняются. Revision, CSRF, идемпотентность и доверенные формы решений не меняются. Числовые лимиты требуют отдельной задачи контроллера. Новые зависимости, комментарии в коде, подавления проверок, commit, merge и приёмка исключены.

## Допущения

1. Пользователь разрешил использовать существующие данные и TASK-006 как основу.
2. Прогресс означает текущий этап: достоверных процентов и списка завершённых этапов в контракте нет.
3. Лимиты означают rate_limited и причину: числовых квот и срока восстановления в контракте нет.
4. Доступность действий определяется только контроллером, состояние задачи полномочий не создаёт.
5. Существующие этапы и действия дорабатываются визуально.
6. Документы TASK-007 сохраняются на этапе исполнения.
7. При неизвестном сочетании состояния и этапа используется иконка ошибки рядом с исходным текстовым описанием.
8. Исходные изменения сопоставлены с планом чтением разрешённых файлов: документов TASK-007 и описанных доработок в начале исполнения не обнаружено. Скрытые данные Git не читались.

## Проверка

Дополнить сценарии ограничения с причиной и без неё, вопроса при ограничении, отсутствия полномочий, пустого списка и фактических действий, неизвестного этапа, компактной подписи и декоративных иконок. Сохранить проверки check → implement → check и различий приёмки и применения.

Контроллер запускает frontend tests, TypeScript, production build и Python unittest discover -s tests -v своим toolchain без установки зависимостей. В локальном окружении node и npm не обнаружены; автоматические проверки не запускались. Проверку controller_check выполняет контроллер.

Человек отдельно проверяет desktop и узкий экран, клавиатурный фокус, длинную причину ограничения, неизвестные состояния и отсутствие данных. Визуальная проверка в этом этапе не выполнена.
