# Автоматическая очистка Git worktree после интеграции и отклонения задач

## Контекст и проблема
В Harness-Kit для безопасного коммита принятого результата создаётся изолированный контроллерный `git-worktree` ([`harness/git_results.py`](file:///Users/twist/tmp/ai/harness-kit/harness/git_results.py)) с веткой `tw/TASK-NNN`. После успешного слияния ветки задачи в основную ветку проекта ([`harness/integration.py`](file:///Users/twist/tmp/ai/harness-kit/harness/integration.py)) каталог `git-worktree` оставался зарегистрированным в Git, что приводило к захламлению вывода `git worktree list`, удержанию файловых дескрипторов и нерациональному расходу дискового пространства.

## Требования

1. **Очистка после интеграции (`apply_accepted`):**
   - Сразу после успешного слияния коммита задачи (`git merge`) в ветку интеграции (`main`), контроллер вызывает `remove_worktree(store, ident)`.
   - Каталог `store.folder(ident) / 'git-worktree'` удаляется через `git worktree remove --force`.
   - Ветка `tw/TASK-NNN` в репозитории сохраняется, обеспечивая идемпотентность `commit_accepted` и проверяемость истории Git.

2. **Очистка при отклонении (`reject_result`) и удалении задачи:**
   - Если для задачи был подготовлен worktree, при отклонении или удалении задачи каталог worktree также безопасно удаляется.

3. **Идемпотентность и восстановление:**
   - Если `prepare_worktree(store, task)` вызывается повторно для задачи, чей worktree был удален, но запись `worktree.json` существует, контроллер восстанавливает checkout из существующей ветки `tw/TASK-NNN`.
   - Повторный вызов `apply_accepted` остаётся идемпотентным и не вызывает ошибок при отсутствующем worktree.

4. **Безопасность:**
   - Удаление ограничено строго каталогом `folder / 'git-worktree'`.
   - При отказе `git worktree remove` выполняется безопасное удаление каталога и вызов `git worktree prune`.
