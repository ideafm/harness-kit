# Решения по результату задачи

По запросу пользователя к существующей приёмке добавляются два операторских
действия: request-changes (вернуть с замечаниями) и reject (отклонить окончательно).
Они доступны только при review/done; не доступны агентскому MCP.

request-changes сохраняет замечания и предыдущий вердикт в истории, возвращает
этап implement в очередь. Предыдущие попытки остаются в событии, счётчик нового
цикла сбрасывается. Допуск по согласованному плану сохраняется: расширение
состава файлов или изменение утверждённых документов не разрешаются.
Команда не запускает новый worker сама; существующий worker продолжит очередь.

reject требует причину и точное --confirm TASK-NNN. Состояние становится
rejected, данные и рабочая копия сохраняются. resume/run/answer не оживляют
окончательно отклонённую задачу. Повторное решение и решение по устаревшему
состоянию запрещаются CAS по state и updated.

Существующий accept по-прежнему фиксирует только приёмку и не применяет diff.
CLI — текущий операторский интерфейс; веб-кнопки требуют отдельного канала,
который не позволит непроверенному preview принять свой результат.
