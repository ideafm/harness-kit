# Редизайн tw-web на Next.js и shadcn/ui

Сначала исследуй доступный snapshot и подготовь спецификацию и план.
Задача поставлена в approve-plan: реализация запрещена до человеческого
утверждения версии. Сейчас нужны документы, список файлов, критерии и
объяснение риска. Ничего не устанавливай и не запускай Node/browser/MCP.

Пользователь посмотрел первую читающую панель и попросил приятный интерфейс
на Next.js с UI-kit. Выбран Next App Router + TypeScript + Tailwind + shadcn/ui.
Контроллер остаётся Python в соседнем harness-kit. Эту папку нельзя читать или
менять. Начальный snapshot не содержит результата TASK-001; не пытайся искать
его в скрытых каталогах и не считай его принятым. Предложи самостоятельную
итерацию нового frontend поверх baseline, без скрытых коммитов и интеграции.

Главный экран: sidebar проектов, требует решения, таблица задач, компактная
карточка с действиями и состоянием в начале. Запрос по умолчанию свёрнут.
Вкладки: обзор, спецификация/план, diff, проверки, ревью, события. На телефоне
карточка и список остаются читаемыми. Русский интерфейс; реальные данные,
пустые состояния, ошибки, skeleton; никаких fake-задач и процентов готовности.
Использовать настоящие shadcn Sidebar/Table/Badge/Tabs/Sheet/AlertDialog/Button/
Textarea/Skeleton/ScrollArea. Системные шрифты без внешнего скачивания.

Управление: создание с auto/approve-plan, запуск, пауза, продолжение, ответы,
версия плана и явное утверждение. Для результата: принять; вернуть с замечаниями;
окончательно отклонить с причиной. Приёмка не применяет diff. Применение отдельное,
до готовности безопасной операции недоступно. Нельзя рисовать работающие кнопки
с фиктивным успехом, менять SQLite или выдавать модели человеческие полномочия.
Preview изолирован от операторского origin. Команда tw-web и порт 47831 остаются.

Контракт существующего читающего MCP: JSON-RPC 2.0, JSON-строки по stdio;
initialize (2025-06-18 или 2024-11-05), notifications/initialized, tools/call.
tools/call возвращает content[0].text с JSON либо isError.
tw_status {} -> {project,tasks,worker}; tw_show {task:positive integer} -> Task;
tw_artifact {task,artifact} -> {task,artifact,text,truncated}. artifact из
specification/plan/summary/diff/checks/review. Task имеет id,state,stage,updated,
request,artifacts и optional question,reason,retry_at,implementation_summary,
review_verdict,approval_mode,effective_approval,plan_version,risk,scope,
approval_reason. Worker содержит running и optional starting,pid,managed_elsewhere.

Операторский API, события и идемпотентность ещё не реализованы: опиши точный
контракт и зависимость от отдельной engine-задачи. Не добавляй его в агентский
MCP, не придумывай, что он уже есть. Допускается план frontend с типизированным
адаптером и подставленным транспортом до появления backend. Реальные действия
потом связываются только с готовыми операторскими методами.

Важный blocker: сейчас harness не подготавливает Node-зависимости и не имеет
проверенного Node sandbox. Hidden paths и сеть запрещены. Контроллер должен
отдельно подготовить runtime/lockfile/dependency tree, гарантировать неизменность,
выделить сборочную копию и связать receipt с хэшами исходников. Не обходи это
unrestricted-запуском. Видимый кандидат Node: /opt/homebrew/Cellar/node/25.9.0_2/bin/node,
но он ещё не проверен. Для Next возможен distDir build, это не решение всей изоляции.

В плане явно раздели: engine/toolchain prerequisites и файлы собственно tw-web.
Оцени risk high и scope large; предложи этапы реализации. Не запрашивай секреты,
SSH, hidden paths или разрешение изменить соседний проект. Если текущие границы
не дают исполнить сборку, зафиксируй это как предпосылку плана, а не утверждай,
что сборка или тесты прошли. Текущая команда проверок покрывает только Python;
нужны отдельно tsc, interaction tests и next build в подготовленном sandbox.
