# B-002 · Общий список задач, бэклог и зависимости

**Статус:** бэклог
**Проект:** Harness Kit — модель задач, контроллер и API
**Связано:** B-001 — исполнители и управление работой; TASK-004 tw-web — UI
**Запуск:** отдельно, после проработки плана; автоматически не выполнять

## Цель

Пользователь видит все задачи своего проекта в общем списке, включая бэклог,
готовую очередь, выполнение и результаты. Фильтры позволяют выбрать нужную
группу. Бэклог не должен существовать только в Markdown вне панели.

## Поведение

- Отдельный явный статус «Бэклог»: задача сохранена, но не допускается к исполнению.
  Отображение в общем списке не ставит задачу в автоматически исполняемую очередь.
- Сохранить различие бэклога, ручной паузы, ожидания зависимостей, лимита,
  согласования, выполнения и человеческой приёмки.
- Можно связать задачу с одной или несколькими предпосылками: «зависит от».
  Показывать ссылки, обратную связь «блокирует» и точную причину ожидания.
- Контроллер запускает задачу только после выполнения всех её зависимостей,
  допуска из бэклога и прочих guards. Повторные проверки не создают дубликаты.
- Завершение конвейера, человеческая приёмка и применение различаются.
  Тип зависимости указывает, нужен ли проверенный результат, приёмка или
  применение. Применение и коммиты не происходят автоматически.
- Передача результата — отдельная проверяемая операция baseline с provenance,
  версиями и хэшами. Одной стрелки между задачами недостаточно для передачи файлов.
- Циклы, зависимость от себя и неизвестных задач запрещены. В первом проходе
  зависимости ограничены одним проектом; межпроектные связи требуют отдельного плана.
- Отклонение предпосылки, доработка или изменение её версии отражаются у зависимых
  задач; устаревший baseline не допускается к исполнению молча. Уже запущенные
  зависимые задачи безопасно приостанавливаются, когда результат перестал подходить.
- Обновление зависимостей выполняется атомарно, сохраняется в событиях и переживает
  перезапуск. Агент не может отменить зависимость, утверждение или защиту доступа.

## Перенос текущего бэклога

Отдельно спроектировать идемпотентный импорт B-001/B-002 и будущих Markdown-записей
в модель контроллера с сохранением идентификаторов/ссылок, без автозапуска.
TASK-004 должна учитывать backend-контракт и показывать доступность функциональности
честно, без фиктивных данных или самостоятельного доступа к SQLite.

## План и критерии

1. Схема задач и переходов, API бэклога/зависимостей и миграция текущих записей.
2. Scheduler guards и тесты циклов, нескольких зависимостей, повторов, отклонения,
   доработки и перезапуска. Проверяемая передача результата независимой задаче.
3. Общий список, фильтры и ссылки зависимостей в UI, interaction tests.
4. Сквозной сценарий: задача в бэклоге видна → допущена в очередь → ожидает
   предпосылку → получает проверенную основу → выполняется и проходит ревью.
