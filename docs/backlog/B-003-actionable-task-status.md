# B-003 · Понятная причина остановки и следующее действие

**Статус:** бэклог
**Проект:** Harness Kit — события, состояние, API и контекст ревью
**Связано:** TASK-004 tw-web — отображение; B-001 — обсуждение и корректировки
**Запуск:** отдельно; автоматически не выполнять

## Проблема и пример

История TASK-003 показывает exit_code=1, успешные повторные проверки, возврат
из review в implement, затем «исчерпаны попытки; нужен человек». Причина
возврата и конкретное требуемое действие в треке отсутствуют. Пользователь
не должен восстанавливать причинную цепочку по JSON и внутренним журналам.
В этом случае причиной ревью был устаревший критерий «изменить только план»
после утверждения реализации, а не последняя неуспешная проверка.

## Требования

- Структурированные события содержат понятный итог, категорию причины,
  краткое доказательство и ссылку на подробности проверки/ревью.
- При остановке сохранять первопричину и последнее существенное замечание,
  отдельно от механизма остановки (порог попыток, лимит, ручная пауза).
- Явно указывать необходимость участия человека: что решить, проверить,
  сообщить или подтвердить. При технической проблеме без вопроса так и писать.
  Рекомендация не выдаёт разрешений и не является новым allowed_action.
- Возврат ревью содержит объяснение дефекта и критерий, по которому вернули.
  Согласование плана и переход к реализации учитываются при построении
  критериев/контекста ревью, чтобы требования планирования не отвергали
  позднее разрешённую реализацию. Не удалять содержательные критерии молча.
- Resume показывает, какой этап продолжен и решена ли причина; сброс попыток
  сам по себе не считается исправлением. Не рекомендовать бесконечные повторы.
- Сводка различает пройденные проверки, оставшиеся проблемы и ручные проверки.
  Не угадывать причину по одному exit_code, вывод и сообщения недоверенные.
- После перезапуска и через API доступны те же причины и следующее действие.
  Исключить секреты и приватные рассуждения из диагностических сводок.

## UI и критерии

TASK-004 показывает причинный трек человеческими фразами, JSON и технические
счётчики — в подробностях по запросу. На основном экране — причина и следующее
действие. Проверить сценарии: красные проверки, дефект ревью, конфликт критериев,
лимит, вопрос, исчерпание попыток и resume. Воспроизвести цепочку TASK-003:
успешные проверки не теряются, показано замечание ревью, не выдуман вопрос
человеку; после возобновления причина не объявляется устранённой без доказательств.
