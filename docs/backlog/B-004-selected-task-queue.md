# B-004 · Выбор задач и автоматическое выполнение очереди свежими агентами

**Статус:** бэклог
**Проект:** Harness Kit — scheduler/API; tw-web — управление очередью
**Связано:** B-002 — бэклог и зависимости; B-001 — наблюдение и корректировки; TASK-004 — UI
**Запуск:** пользователь разрешил автоматически брать следующие задачи; учитывать приоритеты и готовность зависимостей

## Запрос

Пользователь выбирает несколько задач из бэклога, задаёт порядок и запускает
их автоматическое выполнение. Каждую задачу получает свежий агент со свежим
контекстом, чтобы история предыдущих задач не раздувала следующую.

## Поведение

- Выбор задач, изменение порядка, просмотр состава очереди и одна кнопка
  «Запустить очередь». Задачи вне выбранной очереди автоматически не исполняются.
- Сначала последовательное выполнение; ограниченный параллелизм — отдельный
  этап после проверки проектной изоляции, блокировок и зависимостей.
- Для каждой задачи новый экземпляр агента и новый контекст. Не продолжать
  одну бесконечную чат-сессию через весь бэклог. Существующий runner уже создаёт
  отдельные ephemeral-вызовы этапов; сохранить эту границу.
- Контекст формируется из запроса, актуальных инструкций проекта, версии плана,
  ограничений, краткой сводки и явно необходимых артефактов зависимостей.
  Не переносить всю переписку, журналы, приватные рассуждения и секреты.
- Передача файлов между задачами — проверенный baseline с provenance и хэшами,
  не неявное наследование истории агента. Контроль объёма контекста прозрачен;
  обязательные ограничения и критерии не обрезаются молча.
- Контроллер сохраняет очередь и текущую позицию, назначение и результаты;
  после перезапуска продолжает без потери и дублирования задач/процессов.
- Ожидание вопроса, согласования, лимита или зависимости видно вместе с причиной.
  Политику поведения при ошибке и независимых следующих задачах выбрать в плане;
  зависимую работу не запускать на неверном результате.
- Лимит: новые платные этапы не стартуют при >=90%, активные прерываются при
  >=94% (запас до пользовательского порога 96%), продолжение после reset+60
  и свежей проверки. Неизвестный расход блокирует платный запуск.
- Можно приостановить/продолжить очередь и отдельно задачу, изменить ещё не
  начатую часть очереди. Статус показывает завершённые, текущую и следующие задачи.
- Автовыполнение не означает приёмку, применение, коммит, merge или доступ
  к защищённым ресурсам. Действующие проверки и согласование версий сохраняются.

## Критерии

Сквозной сценарий: выбрать три задачи → выполнить каждую отдельным агентом →
передать проверенный результат зависимости → остановиться по лимиту → после
сброса продолжить без дубликатов. Отдельные тесты перезапуска, ошибок, вопросов,
изменения порядка, отмены, повторного нажатия запуска и ограничения контекста.
UI связывает очередь с общим списком задач B-002 и панелью наблюдения B-001.
