# План

1. Отправить существующие коммиты в origin/main.
2. Сохранить формы при ошибке refresh, отдельно блокируя команды и trusted iframe.
3. Проверить сохранение DOM и введённого текста, запрет POST, восстановление и изоляцию проектов.
4. Прогнать frontend/core проверки, зафиксировать и отправить результат; обновить действующую панель проверенной сборкой.

Массовые операции — следующий отдельный небольшой этап по спецификации, после защиты черновиков.

Отправка предыдущих коммитов выполнена: origin/main = 7b4c24a. Реализовано сохранение control/session на временном сбое с отдельным commandsDisabled; обычные команды блокируются и в обработчике, trusted iframe остаётся тем же DOM-узлом с inert. При восстановлении прежней revision ввод сохраняется. При смене проекта сохраняется очистка данных.

Добавлена кнопка удаления непосредственно в строке обоих видов списка. Она выбирает задачу и открывает существующее подтверждение после получения актуального control; для running отключена. POST при открытии/отмене не выполняется.

Проверки: 255 core, 154 frontend, TypeScript/build успешны. В следующем этапе общие чекбоксы должны обслуживать два действия: корзина и очередь. Массовое удаление требует атомарного контроллерного контракта с revision и idempotency, проверкой всех задач перед изменением и без автоповтора после неизвестного исхода.

Обновлённая панель опубликована через integrated-build TASK-012. Browser QA с тестовым API и textarea внутри iframe подтвердил: после 503 iframe сохраняет DOM identity и текст, inert блокирует взаимодействие, восстановление снимает блокировку без сброса. На живой панели открыто и отменено подтверждение удаления TASK-012 из строки; удаление не отправлялось.
