# План TASK-008

## Исправление по замечанию HTTP 409

Существующая реализация сверена с планом. Выполнен сброс ожидаемого режима при окончательном HTTP 4xx; точный повтор после сетевого сбоя сохранён. Сценарий конфликта усилен: checked → select working → 409 → актуальный checked, отсутствие зависшей подготовки, сохранение готовой persistent-ссылки и единственный POST. Спецификация обновлена. Локальные frontend-проверки недоступны из-за отсутствия node_modules; frontend, tsc, build и Python проверяет контроллер после ответа. Новые результаты независимых проверок не заявляются. Browser QA и приёмка остаются человеку.

## Принятый порядок

1. Сверить существующие изменения с планом, сохранить спецификацию и план, опубликовать краткую сводку.
2. Расширить TypeScript-контракты capability, preview, view и операции, сохранив scoped HTTP transport.
3. Реализовать отдельный hook: capability gating, последовательный GET polling, сохранение данных, cleanup и защита от поздних ответов.
4. Реализовать select/refresh, обработку status/error, сохранение pending до POST, точный явный повтор, конфликты revision и ожидание подтверждения GET.
5. Создать компактный компонент на существующих UI-примитивах, передать capability через TaskPanel/TaskCard, согласовать единственную ссылку результата; сохранить приёмку.
6. Добавить сценарные frontend-тесты и транспорта, обновить утверждения существующей карточки под точные причины и название ссылки.
7. Передать контроллеру frontend tests, TypeScript, production build и Python unittest. Реальные ошибки исправлять в пределах разрешённых файлов. Передать человеку Browser QA.
8. Записать результаты проверок; оставить результат на человеческой приёмке без accept, commit и merge.

## Декомпозиция и реализация

Связанные части выполнены последовательно в одной задаче: контракты и состояние → операции и повтор → интеграция UI → сценарные тесты. Дополнительные агенты не использовались. Backend, harness-kit и TASK-007 не изменялись. Сверка показала исходную карточку TASK-006 без реализации просмотра.

Добавлены use-project-view и ProjectView. Capability передаётся существующим маршрутом TaskPanel → TaskCard. Транспорт не менялся: его scoped URL и заголовки проверяются новым сценарием. Слот pending просмотра независим от TaskActions. TaskCard использует единственную ссылку «Открыть результат» из нового блока; остальные действия сохранены.

## Передача проверок

При продолжении существующие изменения сверены с планом и замечаниями. Исправлен приоритет состояния: ожидание команды не скрывает ошибку, остановку или отсутствие из GET. Ожидание режима сбрасывается при подтверждённой готовности. Добавлены сценарии терминальных состояний после succeeded, refresh с pending/operations и позднего ответа операции другого проекта. Изменены только разрешённые файлы. Каталог node_modules отсутствует; новые проверки переданы контроллеру, независимый успех не заявляется.

Локальные frontend-проверки недоступны в изолированной копии. Установка зависимостей и обращение к внешним инструментам не выполнялись. Выполнена статическая сверка исходников; независимых результатов тестов нет.

Контроллер выполняет Vitest, tsc --noEmit, next build --webpack и предоставленный controller_check Python unittest discover. Проверки контроллера агент не запускал. Итоговые receipts и реальные ошибки необходимо оценить перед приёмкой.

## Browser QA для человека

1. На desktop и mobile открыть карточку: блок компактен, кнопки переносятся, длинные digest и адрес не разрушают раскладку.
2. Проверить отсутствие, остановку, подготовку, ошибку и предыдущую версию; reason/message/error видны как текст.
3. При активной другой задаче увидеть предупреждение, выбрать checked/working явно; выбор карточки runtime не меняет.
4. После succeeded дождаться подтверждающего GET: сборка не объявляется готовой преждевременно.
5. Проверить рабочую неподтверждённую версию, постоянный адрес и task-bound ссылку результата с параметрами.
6. Отключить сеть, восстановить страницу и явно повторить прежнюю операцию; другой проект/задача её не наследует.
7. Проверить readonly и отсутствие capability, сохранность вкладок, worker, решений и человеческой приёмки.

Browser QA не выполнен. Принятие, commit и merge оставлены человеку.

## Уточнённый контракт и исправление Browser QA

Продолжение по последнему result_feedback: существующие изменения сверены с планом. Исправлено только распознавание legacy preview: read_only исключён из признаков нового persistent-контракта. Добавлена регрессия {url, read_only:true} без capability с проверкой ссылки, отсутствия GET/POST, кнопок и утверждения готовности. Строгие проверки persistent сохранены. Новых функций и общего рефакторинга нет.

Локальные frontend-проверки недоступны: нет node_modules, Node.js и npm не найдены. Проверки выполняет контроллер после передачи результата. По предоставленному feedback основные Browser QA сценарии уже прошли; агент их независимо не повторял. Результат оставлен на человеческой приёмке без merge и commit.

Существующие изменения сверены с планом и result_feedback. Верхний data.revision используется только для If-Match. requested.revision содержит UUID выбора; опубликованный view.revision должен равняться requested.revision + ":" + source_digest. Модель и валидация включают view.revision. Готовность дополнительно требует согласованных requested.task/mode, active_task, current, running и отсутствия building/error. Неполные сведения, включая отсутствующий requested, не подтверждают готовность.

Persistent-ссылка требует строкового preview.version, равного source_digest, а также подтверждённой готовности выбранной задачи, совпадения режима, current=true и read_only=true. Используется только task-bound preview URL с сохранением пути и параметров. Legacy fallback сохранён. Основной вид показывает короткую версию; UUID и полные digest/revision находятся в закрытых подробностях.

Регрессии используют разные UUID выбора и SHA256 токен If-Match, реальную view.revision и совпадающую версию preview. Проверяются переход succeeded → подготовка → готовность, несовпадающая/отсутствующая/числовая preview.version, неверные UUID и digest опубликованной ревизии, отсутствие requested и независимость готовности от токена If-Match.

Локальные frontend-проверки недоступны: node_modules отсутствует. Зависимости не устанавливались. Frontend tests, TypeScript, build и Python unittest переданы контроллеру; независимые проверки не запускались. Browser QA и окончательная приёмка остаются человеку.
