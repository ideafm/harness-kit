# План: Обратимое удаление задачи и вкладка «Удалённые»

**Спецификация:** `docs/specs/2026-11-08-reversible-task-deletion.md`
**Статус:** остановлено до согласования архитектурных границ

---

## 1. Этап 1: Поддержка обратимого удаления в контроллере (`harness/**`)

- [ ] **1.1. Модель данных и исключение из очереди (`harness/state.py`):**
  - Добавить состояние `trashed` в `STATES` (или поле `deleted: True` в метаданных).
  - В `Store.runnable()` исключить задачи в состоянии `trashed` из списка задач, запускаемых воркером.
  - Реализовать `Store.delete(ident)` с проверкой запрета удаления задач в состоянии `running`.
  - Реализовать `Store.restore(ident)` с возвратом задачи в безопасное состояние (`paused`) без автоматического запуска.
- [ ] **1.2. Сервис и полномочия действий (`harness/service.py`, `harness/operator.py`):**
  - Добавить действия `delete` и `restore` в `ACTIONS`.
  - В `Operator.control(ident)` формировать `allowed_actions`:
    - Добавлять `delete` только если `state != 'running'`.
    - Для удалённых задач предоставлять только `restore`.
  - В `capabilities()` возвращать поддержку обратимого удаления.
- [ ] **1.3. Обработка API (`harness/web.py`):**
  - Поддержать `action: 'delete'` и `action: 'restore'` в `POST /api/v1/tasks/{id}/actions`.
  - В `GET /api/v1/status` разделять или маркировать удалённые задачи.
- [ ] **1.4. Тесты контроллера:**
  - Тест: удаление переводит задачу в `trashed`, задача не появляется в `runnable()`.
  - Тест: удаление задачи в состоянии `running` отклоняется с ошибкой.
  - Тест: восстановление возвращает задачу в исходный список, не запуская воркер.

## 2. Этап 2: Поддержка в веб-интерфейсе (`web/**`)

- [ ] **2.1. Вкладки списков задач:**
  - Добавить переключатель вкладок над списком: «Задачи» / «Удалённые» со счётчиками.
  - Фильтровать отображение задач по выбранной вкладке.
- [ ] **2.2. Действие «Удалить» в карточке:**
  - Добавить кнопку «Удалить» в блок действий `task-actions.tsx`.
  - Для работающей задачи кнопку отключать с пояснением *«Работающую задачу удалить нельзя»*.
  - По нажатию открывать диалог подтверждения удаления.
- [ ] **2.3. Восстановление задачи:**
  - Во вкладке «Удалённые» отображать кнопку «Восстановить».
  - По клику отправлять `{action: 'restore'}` через существующий транспорт.
- [ ] **2.4. Тесты интерфейса:**
  - Тесты отображения кнопки «Удалить», модального подтверждения и блокировки при `running`.
  - Тесты переключения вкладок и кнопки «Восстановить».

---

## 3. Блокирующий архитектурный фактор

- Проект Tw `web` ограничен каталогом `web/` и не имеет прав доступа к `harness/**`.
- Реализация задачи в `web` без предварительной поддержки в контроллере `harness` невозможна без нарушения запрета на клиентскую имитацию.
- Корень `harness-kit` в данный момент не инициализирован как проект Tw.
- Согласно инструкциям пользователя:
  > *«Если выбранный проект Tw не позволяет охватить нужные файлы контроллера и web/, сообщи об этом до реализации; не обходи границу рабочей копии.»*
  Работа приостановлена до указания оператора о способе преодоления межпроектной границы.
