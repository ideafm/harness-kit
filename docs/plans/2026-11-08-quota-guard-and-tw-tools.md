## Этап 1. Quota Guard: семантика окон, порог 95% и разделение причин паузы

### Задачи
- [x] 1.1. В `harness/quota.py` обновить логику порогов останова:
  - 5-часовое окно (`primary` у Codex, `gemini-5h` у Gemini, `300` мин): остановка при `used_percent >= 95.0%`.
  - Недельное окно (`secondary` у Codex, `gemini-weekly` у Gemini, `10080` мин): остановка при `used_percent >= 95.0%`.
  - Заменить устаревшие пороги (90/94% и 96%) на 95.0%.
  - Расширить диапазон пользовательского `stop_percent` в `quota-policy.json` до 95.0% (`0 < cap <= 95`).
- [x] 1.2. Разделить причины и логику паузы в `Guard`:
  - **Штатная пауза по квоте ($\ge 95\%$):** `QuotaPause(..., resets_at + 60)`. Задача переходит в `rate_limited` и ждёт сброса окном провайдера.
  - **Защитная пауза при ошибке чтения/проверки:** `QuotaPause(..., now + 60)`. Не подтверждает сброс квоты, при возобновлении источник опрашивается заново. Попытки этапа (`attempts`) не списываются.

### Критерии приёмки
- Тесты на граничные значения: 94.9% разрешает шаг, 95.0% вызывает `QuotaPause(resets_at + 60)`.
- Ошибка сервиса квот переводит задачу в `QuotaPause(now + 60)` без списания `attempts`.
